# 01 — 没有任何读取面能超过工具结果上限

**What to build:** 任何读取工具,在**任何参数下**,返回的都是一份读得完的结果 ——
要么落在上限内,要么分页。今天有读取面会直接把结果撞爆,而调用方拿到的是一条错误,
不是数据。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

## 已知的两个实例

- **`lane_check`** —— 生产上返回 128,100 字符,结算 agent 拿到的是错误,**那一轮等于没有校验器**。
  已修(`6e668da`):`page` / `pageBudget`、同类聚合、续读提示。**这就是本票要照搬的形状。**
- **`recall(id="E<n>", page=2)`** —— 段卡片的第 2 页(全部字段行 + 成员索引)返回
  **169,362 字符**,而调用带着显式的 `pageBudget: 3000`。上限是
  `WORKER_TOOL_RESULT_MAX_CHARS = 100_000`。**未修。**

两次的形状相同:一个渲染器把一个无界集合一次性铺开,而它的预算参数在那条路径上不生效。

## 本票的重点不是修那一个

`lane_check` 是结算 agent 撞的,段卡片是我撞的 —— **下一个是谁撞、撞哪一个,没人知道**。
所以先做**普查**,再修:

- [ ] 枚举每一个读取工具的每一条渲染路径(`recall` 的各 id 形式与页码、`timeline` 的
      各 view 含 `E<n>/L*`、`lane_check`、段卡片、console 的 API 响应),对每一条回答:
      **它的输出有上界吗?上界由什么保证?** 结论列成一张表,含无界的那些
- [ ] 对每一条无界路径:接上与 `recall` 同名同义的 `pageBudget`,溢出翻页、**永不截断块**,
      每页带续读提示。不要为某一条新造一套分页词汇
- [ ] `timeline(id="E<n>/L*")` 是已知的一条 —— 它一次渲染全部已声明泳道,E60 今天 103 条,
      而且**不接任何预算参数**。结算提示为此专门绕开它、只教单条形式(`f38dca9`),
      那是止血不是修复
- [ ] 每条修好的路径都要一条**上界断言**:用确定性的大 fixture,断言默认调用的字节数
      小于 `WORKER_TOOL_RESULT_MAX_CHARS`
- [ ] **上界断言与分页断言不得合并**。fixture 恰好装得下一页时,把预算调成无穷什么都不变,
      上界断言照样绿而分页整个是死的 —— 这在 `6e668da` 上实测发生过:
      预算设为无穷时上界断言停在 95,048 字符,依然绿
- [ ] fixture 必须**提交进仓库且确定性**,不得读生产库(套件有 HOME 沙箱),
      也不得用玩具规模 —— 玩具形状漏掉的正是真实规模才出现的那次失败

## 不在范围内

- 改任何一条路径**渲染什么**。本票只保证「读得完」,不重新设计报表内容
- 聚合/折叠。`lane_check` 需要它是因为它有字面重复的警告族;别处不要顺手引入
