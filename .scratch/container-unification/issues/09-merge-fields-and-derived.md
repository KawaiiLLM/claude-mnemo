# 09 — 合并的字段与派生状态

**What to build:** 合并之后,目标任务的字段、派生 facet、全文索引和写授权都是自洽的。

对应 spec:D7 + D6 第 5 步。

**Blocked by:** 08(merge 主干)

**Status:** ready-for-agent

- [ ] 六个 row-list 字段追加 + 完全相同的行去重;`title` 保留目标的;
      `content`/`insight` 空行分隔追加
- [ ] **`type` 重算**——它是从全部成员派生的 facet,不是状态列。搬进一批成员,目标的 type 就变了
- [ ] **目标端 FTS 重建**放在最后一次行更新之后,连同目标的引用重推。
      FTS 不跟随 SQL 自动同步,而 type 重算可能在字段合并**之前**就索引过一次
- [ ] **源端清理**:`memory_fts` 的段行、三张 write_gate 多态表的源行——都没有段外键,不会自动走
- [ ] **目标被改写的八个字段必须在同一事务内盖写闸戳**,否则一个合并前完整读过的写者
      可以用旧文本覆盖回去,静默抹掉刚导入的内容
- [ ] 测试:源的搜索命中消失、目标的搜索命中出现
- [ ] 突变:去掉目标端 FTS 重建,必须有测试变红
