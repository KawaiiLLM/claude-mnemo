# 05 — 边带两侧 tag(expand):加列、加侧索引、双写

**What to build:** 一条边可以携带两侧 tag —— 弧尾是引用方所属 lane,弧头是被引用方所属 lane。这一票只做**扩张**:新列与新索引就位并在写入时与旧列同步,读者仍然读旧列,行为零变化。

**Blocked by:** 01(迁移位置)、03(存量词表先归位)。

**Status:** done — landed, not released

- [ ] 两列 `tail_tag` / `head_tag`,**`NOT NULL` + 空串哨兵表示未结算**。SQLite 的 UNIQUE 不去重 NULL,可空列会让同一条未结算的边可以重复插入 —— 哨兵让唯一键、比较与索引都保持朴素,代价是「空串 = 未结算」这条约定必须写在列注释里。
- [ ] 边的身份键变为 `(citing, cited, relation, tail_tag, head_tag)`;一条测试重复写入同一条完全未结算的边,断言只留一行。
- [ ] 侧索引:`(edge_row_id, side, tag)`,主键 `(edge_row_id, side)`(每侧单值),二级索引 `(side, tag, edge_row_id)`。重建测试必须断言**侧**,不能只断言边行。
- [ ] 迁移把旧 `tags` 内部化:单 tag → 两侧同值;多 tag(41 条,8.8%)拆成多条边;`tags='[]'` → 两侧空串,即**未结算**。
- [ ] **「无损」只对当前快照成立**:现行唯一键允许同一 (pair, relation) 上并存 `{a}` 与 `{a,b}`,拆分后都产生同一身份键。生产上此形状实测为 0,但仍要走与票 03 相同的合并规则,并把合并计数写进收据 —— 一条单独的测试覆盖它,「多 tag 拆分后两侧一致」那条分辨不了。
- [ ] 双写:所有写入路径同时维护新旧两处,读者不变,全部现有测试保持绿。

## 票 01 落地后加的两条约束

- **新收据不要用 `lane-declaration-` 前缀**,除非它真的是注册表的一个阶段 —— 现有的端到端测试把这个前缀**当作阶段集合来计数**,借用它会静默破坏那条断言。
- 迁移跑在 `initializeSchema` 的 `runLaneModelV12EdgeMigration` 槽位里,那个槽位已经有一道拦截:注册表未全部结算时它拒绝运行。同时 `runLaneRegistryMigration` 里另有一道拦截,任何阶段仍待办时拒绝面对已 v12 化的 `memory_edges` —— **所以列改动无论写在哪里都会被抓到**,不要试图绕过槽位。
