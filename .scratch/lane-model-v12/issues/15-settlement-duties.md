# 15 — 结算的职责收成两件,并获得 merge

**What to build:** 结算只做两件事 —— 改 turn 的字段(含边),以及 lane tag 的 `declare` / `undeclare` / `merge`。段整块不再归它。

**Blocked by:** 14(段的归属改为自动推导之后,结算的段动词才失去最后的用途)。

**Status:** ready-for-agent

- [ ] 结算门面的 `propose`、`reassign`、`create` **退役** —— 从枚举里移除,让过期调用拿到 zod 自己的「非法枚举值」并列出合法动词,这是 `assign` 退役时用过的手法。
- [ ] `proposals` 注入块随 `propose` 一同退役;它唯一的消费者是主 agent 采纳建段提案,而段已改为自动挂靠。
- [ ] **新增 `merge`**:把 lane tag A 并进 B。**原子地**改写全部成员 turn 的 tags(A→B,已带 B 的去重)与全部边的两侧 tag(A→B),然后撤销 A。半并的状态不允许存在 —— 数据与收据同事务,failpoint 重启测试。
- [ ] `merge` 的拒绝:A 与 B 不在同一个段、任一方未声明、A 与 B 相同 —— 每条点名缺口。
- [ ] 合并后若产生同一身份键的重复边,走既有的合并规则(asserted 的审计元数据存活,同级取较早),并把合并计数写进收据。
- [ ] 结算提示词的职责段重写成这两件事;不再出现段的创建、挂靠、提案。
- [ ] 突变验证:关掉原子性(先撤 A 再改成员)必须让一条测试变红。
