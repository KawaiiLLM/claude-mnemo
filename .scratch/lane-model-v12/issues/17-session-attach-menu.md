# 17 — 会话挂靠哪个段,由用户从菜单里选

**What to build:** 一个会话挂靠哪个段,由用户在 Claude Code 里手动选一次 —— 这是 turn 归属自动化之后唯一没有主人的那个决定。

**Blocked by:** 14(段收成一个唯一 tag 之后,菜单里每一项才是一个名字而不是一组)。

**Status:** ready-for-agent

turn 的归属由 tags 自动推导,但**会话**挂靠哪个段决定的是**注入哪几张卡片**,和 turn 归属是两件事。收窄之后主 agent 不再管段、结算也不管,这个决定没有主人。

插件今天只有 `hooks` / `scripts` / `skills` 三个目录,没有 `commands/` —— 本票新增一个,用的是插件本来就支持的形状。

- [ ] 一个菜单式命令列出当前活着的段(`E<n> 标题 — #tag`),用户选一个,本会话即挂靠它;可以再选一次改挂,也可以取消挂靠。
- [ ] 挂靠状态按会话持久化,与现有的 `remember(attach)` 写同一处 —— 这是换入口,不是换机制。
- [ ] 未挂靠时注入只有花名册(段词表);挂靠后出现该段的卡片(段 tag + 段内 lane 词表)。这条流程本身要有测试。
- [ ] 最多三个卡片槽的既有上限不变。
- [ ] `remember(attach)` 是留着(给用户让 agent 代劳的情形)还是退役,在本票里裁并说明理由。

## `attach` 还剩什么用(裁决 [S15069/T1663])

它今天做三件事,v12 之后死一件、活两件:

| | v12 之后 |
|---|---|
| 记录会话→段的绑定 | **活着** —— 决定 SessionStart 注入哪几张卡片 |
| 把卡片作为**工具返回值**吐回来 | **活着,而且更重要**(见下) |
| 当闸:`note(segment=...)` 拒绝未挂靠的段 | **死了** —— 归属改由 tags 推导,那个参数本身退役 |

第二条变重要的原因:**注入块只在 `SessionStart` 上发**(startup / resume / compact),`UserPromptSubmit` 上只跑 session-init 与 prompt-dispatch。**会话中途挂靠,卡片不可能靠注入送达,只能靠返回值。**

## 自动挂靠(裁决 [S15069/T1663],待用户确认)

- [ ] **第一次把某个段 tag 写进 `tags` 时,会话自动挂靠该段**,并把卡片放进那次写入的返回值里。
- [ ] 这消掉一个循环依赖:要知道有哪些 lane 得看卡片、要看卡片得先挂靠、要挂靠得先知道挂哪个 —— 而**花名册足以回答最后一问**,所以链条能自己启动。
- [ ] 菜单因此从「唯一入口」变成**覆盖入口**:还没写任何东西就想先挂靠、想改挂、想取消挂靠,走菜单。

## 没挂靠时的行为(已裁,不是错误状态)

花名册始终注入且带着段词表,所以**段归属照常发生**;只有 lane tag 留空(lane 词表在卡片上),由结算补齐。**降级是精确的,不是失效。**
