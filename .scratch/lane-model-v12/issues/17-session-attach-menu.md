# 17 — 会话挂靠哪个段,由用户从菜单里选

**What to build:** 一个会话挂靠哪个段,由用户在 Claude Code 里手动选一次 —— 这是 turn 归属自动化之后唯一没有主人的那个决定。

**Blocked by:** 14(段收成一个唯一 tag 之后,菜单里每一项才是一个名字而不是一组)。

**Status:** done(未发版)

turn 的归属由 tags 自动推导,但**会话**挂靠哪个段决定的是**注入哪几张卡片**,和 turn 归属是两件事。收窄之后主 agent 不再管段、结算也不管,这个决定没有主人。

插件今天只有 `hooks` / `scripts` / `skills` 三个目录,没有 `commands/` —— 本票新增一个,用的是插件本来就支持的形状。

- [x] 一个菜单式命令列出当前活着的段(`E<n> 标题 — #tag`),用户选一个,本会话即挂靠它;可以再选一次改挂,也可以取消挂靠。
      —— `plugin/commands/attach.md`(`/claude-mnemo:attach`),插件的第一个 `commands/` 条目。列表本身由 `remember(attach)` **不带 `id`** 返回,所以它是可单测的代码,不是模型的自由排版;未命名的段渲染为 `(unnamed)`(十个活段里九个如此)。
- [x] 挂靠状态按会话持久化,与现有的 `remember(attach)` 写同一处 —— 这是换入口,不是换机制。
- [x] 未挂靠时注入只有花名册(段词表);挂靠后出现该段的卡片(段 tag + 段内 lane 词表)。这条流程本身要有测试。
      —— `tests/hooks/session-attach-flow.test.ts`。
- [x] 最多三个卡片槽的既有上限不变。
- [x] `remember(attach)` 是留着(给用户让 agent 代劳的情形)还是退役,在本票里裁并说明理由。**裁决:留着**,见下。

### 裁决:`attach` 留着(本票)

留着,理由是它的第二件事**没有替代品**,而且这次收窄之后反而只剩它一个通道:

1. **注入块只在 SessionStart 上发**,`UserPromptSubmit` 只跑 session-init 与 prompt-dispatch(`plugin/hooks/hooks.json`,有测试钉住)。会话中途挂靠 —— 无论是用户走菜单还是自动挂靠 —— 卡片只能作为**工具返回值**回来。退役 `attach` 就是退役这条通道。
2. **菜单命令是一段 prompt,不是一套机制**。它能工作,正是因为它调 `remember(attach)`;把动词退役,菜单跟着一起没。
3. 自动挂靠与「取消挂靠」都要落到同一张 `segment_attachments` 表上,**换入口不换机制**这条要成立,就得有动词。

死掉的仍然是第三件事(当闸拒未挂靠的段):`note(segment=...)` 参数本身已随票 14 退役。

**新增 `detach`**:ADR-0005 当初「不设 detach」的前提是每一行绑定都是人主动做的,所以不会积攒出没人要的行。自动挂靠把这个前提打掉了(一次 tags 写入就是一次绑定),所以必须有回头路。`detach` 只删绑定行(票 23 起另记一行「这个会话拒绝这个段」,只有自动挂靠读它),不碰段、不碰归属、不碰任何 grant。

## `attach` 还剩什么用(裁决 [S15069/T1663])

它今天做三件事,v12 之后死一件、活两件:

| | v12 之后 |
|---|---|
| 记录会话→段的绑定 | **活着** —— 决定 SessionStart 注入哪几张卡片 |
| 把卡片作为**工具返回值**吐回来 | **活着,而且更重要**(见下) |
| 当闸:`note(segment=...)` 拒绝未挂靠的段 | **死了** —— 归属改由 tags 推导,那个参数本身退役 |

第二条变重要的原因:**注入块只在 `SessionStart` 上发**(startup / resume / compact),`UserPromptSubmit` 上只跑 session-init 与 prompt-dispatch。**会话中途挂靠,卡片不可能靠注入送达,只能靠返回值。**

## 自动挂靠(裁决 [S15069/T1663],边界见票 23)

- [x] **一次归属写(把某个段 tag 写进 `tags`)后,若会话尚未挂靠该段、且未显式 detach 过它,会话自动挂靠该段**,并把卡片放进那次写入的返回值里。
      —— 措辞按票 23 校准:原文写的「第一次」从来不是实现,实现是「写完属于某段就断言绑定」(见本节末的实现取舍);票 23 又加了两道边界(只对 caller 自己会话的 turn、detach 后不重挂)。
- [x] 这消掉一个循环依赖:要知道有哪些 lane 得看卡片、要看卡片得先挂靠、要挂靠得先知道挂哪个 —— 而**花名册足以回答最后一问**,所以链条能自己启动。
- [x] 菜单因此从「唯一入口」变成**覆盖入口**:还没写任何东西就想先挂靠、想改挂、想取消挂靠,走菜单。

已实现,并**刻意留成可单独摘除的一块**:全部落在 `src/mcp/note.ts` 的一个 if 里(挂靠)加收据里的一个 if(卡片),用户若否掉这条裁决,删这两处即可,`attach`/`detach`/菜单一行不动。摘除后要认的代价:未挂靠的会话看不到 lane 词表,lane tag 留空由结算补齐 —— 也就是本票最后一节说的那个「精确降级」,只是它会从少数情形变成默认情形。

一处实现取舍(比裁决的字面更宽,写在这里而不是藏在代码里):挂靠条件是「这次 tags 写入之后该 turn **属于**某个段」,不是「归属发生了**变化**」。理由是绑定是幂等断言,而一次不改变归属的重写同样说明这个会话正在那个段里干活;卡片仍然只在**真正新建了绑定**的那一次回来。

**票 23 收窄了这条的两侧**(peer B2 指出实现比票面宽):写的必须是 **caller 自己会话的 turn**(跨会话 `note` 不改 caller 的注入面),且该会话没有显式 detach 过这个段(detach 按 (会话, 段) 记账,`segment_detachments`)。`detach` 之后回来只有菜单与 `remember(attach)` 两条路,两者都会清掉那条记账。

## 没挂靠时的行为(已裁,不是错误状态)

花名册始终注入且带着段词表,所以**段归属照常发生**;只有 lane tag 留空(lane 词表在卡片上),由结算补齐。**降级是精确的,不是失效。**
