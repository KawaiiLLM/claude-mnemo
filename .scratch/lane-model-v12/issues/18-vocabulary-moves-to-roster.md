# 18 — 词表搬到花名册,卡片只讲状态

**What to build:** 一个会话能写的全部 tag 出现在同一个地方 —— 花名册列出每个段的那一个 tag,**已挂靠的那个段展开出它的 lane 词表**;段卡片不再承载任何词表。

**Blocked by:** 14(段收成一个唯一 tag,且卡片的直方图行退役之后再动)。

**Status:** ready-for-agent

裁决 [S15069/T1670]。决定性的理由是实测出来的**预算不对称**:

| 块 | 现状 | 上限 |
|---|---:|---:|
| `segment<n>-fields` | **1972 token** | 2000 —— **贴顶,散文字段今天就在被切** |
| `roster` | **289 token** | 槽约 2400 token |

把一份词表从满的块搬到空的块。另外两个好处顺带拿到:**花名册成为唯一的词表面**(`tags` 能装的两类词都在一处,与模型一一对应),而且**它不在省略阶梯里** —— 卡片会降级到 500 token 并连带砍掉词表,花名册不会。

实测渲染(E60 取成员数前 25 条 lane,11 个段):**995 字符 / 279 token —— 比今天的花名册 289 还少。** 省下来是因为 tag 排在行首、标题只留够判断归属的长度。

- [ ] 花名册每行以**可写的 tag 开头**,其后是段 id 与一句足以判断「这一轮属于哪个段」的短标题。
- [ ] **已挂靠的段展开一行 lane 词表**(纯 tag,`·` 分隔);未挂靠的段不展开。
- [ ] 段卡片删掉 `- lanes:` 行 —— 连同票 14 已删的两条直方图,卡片回到纯粹讲这个段的**状态**(goal / constraints / decisions / next_steps),不讲词表。
- [ ] **不设计降级方案**(裁决 [S15069/T1667]):装不下是 lane 增殖的症状,不是渲染格式的问题。判据执行到位时 20–30 条只要 160–250 token。
- [ ] 测试:未挂靠时花名册无 lane 行;挂靠后出现且只出现该段的;卡片不再含任何词表行;整块 token 数与今天的花名册同量级。
