# 20 — 缺任一侧 tag 的边是草稿:算作无边,但结算必须报 error

**What to build:** 边只要有**任意一侧**没有 tag,就是草稿形态 —— 参与不了任何计算,但结算看得见它欠着。

**Blocked by:** None。

**Status:** done — landed, not released

## 裁决(用户,2026-08-26)

> 边上只要**任意一侧**没有 tag 就是草稿形态,**计算时视为无边**,但**结算的 commit 和检查工具应该出 error 提示**。

## 这推翻了票 08 的一条

票 08 现在把**半挂**(只有一侧有 tag)在写入时**直接拒绝**(`src/shared/turn-phase.ts:377-393`,错误类 `lane-half-settled`)。新裁决说它是**合法的草稿**,不是非法状态 —— 拒绝的位置从**写入闸**搬到**结算的 error 报表**。

- [ ] **写入闸接受半挂边** —— `lane-half-settled` 那条拒绝退役。两侧皆空当然也接受(本来就是主 agent 的常态输出)。
- [ ] **计算时视为无边**:`laneMembershipClaims` 对任一侧未 settled 返回空 —— 这条**现在已经成立**,加钉桩确认,不要重写。
- [ ] **校验器新增一个 error 类**:任一侧为空的边,点名地址与缺的是哪一侧。它是 **error 不是 warning** —— 与 E3/E4 同级,进 ERRORS 块。
- [ ] **`commit` 在写入范围内还有草稿边时拒绝**,与其他 error 一致;范围外的草稿边是别人的活,不拦。
- [ ] 结算教学面(`lane_check` 与 `commit` 的描述)把新错误类列进那张封闭清单 —— 那张清单是封闭枚举,漏一个就是教一个不会到来的拒绝的反面:一个不被解释的拒绝。
- [ ] 票 11 把「无归属簇」定义成「两侧皆空的边」并作为 **warning**;本票让**任一侧为空**成为 **error**。两者关系要在实现里裁清楚并写明:建议 warning 保留为「成簇的规模事实」,error 承担「逐条待办」,不要重复报同一条边两次而不说明。
- [ ] 突变验证:关掉 error 类、关掉 commit 拒绝,各有点名的测试变红。
