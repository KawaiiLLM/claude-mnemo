# v12 批次留给用户的裁决

十八票全部落地、未发版。下面每一条都是**实现中撞出来的设计问题**,我没有替你裁——它们要么与你写下的 spec 文本冲突,要么会改变模型的行为边界。按需要裁决的紧迫程度排序。

## 1. 收敛判定:弧尾单独说了算,还是两侧都要同意?(最重要)

**订正(peer 审查后):我最初的措辞不准。** 那句「宣告收敛的是弧尾 tag 所指的那条 lane」在 `rubric-v12-shared.md` 里,而**现行 normative 的 `rubric-v12-concepts.md` 已经把它删掉了**,只剩「通过 index 宣告收敛的那个节点」。所以现行权威文本对「弧尾单独说了算 vs 两侧都要同意」**根本没有答案** —— 这不是代码违背 spec,而是 spec 缺了一句。**无论你裁哪边,都必须把结论写回 concepts**,否则「一个属于多条 lane 的节点,它的一条 index 到底关闭哪条 lane」永远没有权威答案。

Peer 独立裁的是**弧尾单独说了算**,理由是三个谓词被合并成了一个(详见 `peer-review.md` B1):`internal`(两侧都是 L,管连通)、`closes`(`index` 且弧尾是 L,管收敛)、`coreTarget`(= internal)。现在 `laneMembershipClaims` 正确实现了第一个,却被归约循环复用来实现第二个。

**代码现在要求两侧同时指向该 lane 才承认这条 index 是终点。**

分歧的来源是两个不同的问题被同一个谓词回答了:

| 问题 | 正确的口径 |
|---|---|
| 这条边算不算 lane **内部**的连线(连通性) | 两侧都要是这条 lane |
| 这个节点算不算**宣告了自己这条 lane 收敛** | 你的文本说:只看弧尾 |

按现在的代码,**一个成员发出的收尾 index 如果指向另一条 lane,它自己那条 lane 就永远关不上。** 这在跨 lane 汇聚(「我这条线收工了,成果并进主线」)这个最自然的收尾姿势上直接失效。

**我没有改**,因为票 06/09 特意用测试把「两侧一致」钉死了并写了理由,而那些测试针对的是**跨段**的情形——跨段与段内跨 lane 不是一回事。改动很小(归约循环里的一处),但它改变模型语义,应该你裁。

## 2. 自动挂靠(票 17,票面标注「待用户确认」)

已实现:**第一次把某个段 tag 写进 `tags` 时,会话自动挂靠该段**,卡片随那次写入的返回值回来。

理由是它解掉一个循环依赖:要看 lane 词表得有卡片、要卡片得先挂靠、要挂靠得知道挂哪个——而花名册能回答最后一问,所以链条能自启动。

**保持可分离**:删掉 `note.ts` 里两个 `if` 就回到纯手动,`attach`/`detach`/菜单都不用动。代价是未挂靠的会话看不到 lane 词表,lane tag 一律留空等结算补——票面称之为「精确的降级」,只是从少数情况变成默认情况。

## 4. rubric 瘦身丢掉的两块内容

拆分之后,v11 有而 v12 没有:

- **建段指引**——「先看花名册,能挂就挂,都不合适才建,按任务真实形态命名」。主 agent 现在拿不到任何建段判据。

两块都是**设计上的后果**(行动原则只发给主 agent),不是遗漏。补回去要改 rubric 源文件,是内容决定,我没动。

## 5. 段 tag 的全局唯一性有个缺口 —— **peer 判为 bug,不是裁决;已列入待修**

`insertLane` **不拒绝**一个与**另一个段的段 tag** 同名的 lane tag。于是一个 lane 词可以遮蔽一个段词,而把成员折进它会改变那个 turn 推导出来的归属。

这是票 14「段 tag 全局唯一」没关严的口子,不在票 15 范围内。`merge` 已经显式重新推导归属,所以行为一致;但**闸本身还有洞**。

## 6. 两个较小的口径

- **票 13 的 C3**:「有边但两端都无任何已声明 lane 的节点数」有两种读法——「节点有边且不带已声明 lane」(超集,现在的主数字)与字面的「边的两端都不带」(子集,作为具名上下文行打印)。要换主数字是一行。
- **票 11 的归属告警**:「无归属簇」重新定义为「两侧皆空的边」之后,在迁移前存量上会把 3 个小簇塌成 1 个 54-turn 的大簇。这是诚实的欠账全貌(结算做完就自动安静),但在追上之前这条告警几乎没有区分度。较窄的读法(保留节点过滤,只换连接词)当时也可选,worker 判断那会让你那句话变成空操作。
