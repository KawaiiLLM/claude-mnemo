# Lane model v12 — spec (Rev 2)

**状态**:未实现。lane-declaration 批次(12 票 + 2 张修理票)已落地未发版,本 spec 建立在它之上并改写其中若干条。

**正文来源**:模型的权威文本是用户自己写的两份 rubric ——
`rubric-v12-shared.md`(主 agent 与结算共享)与 `rubric-v12-settlement.md`(结算专用)。
本 spec 与它们冲突时以 rubric 为准。

**贯穿全篇的约束**:**选举机制与校验器只做最小调整。** 这套定义还没有被真实数据验证过,凡是「重新设计报表 / 重新设计评分」的动作一律推迟到验证之后 —— 见最后一节。

**Rev 1 → Rev 2**:一轮 peer 评审,17 条采纳。最重的四条:M-B 在**真实生产数据上已经撞键**;M-A 的「无损」只对当前快照成立;v12 迁移与未发版的 lane-declaration 迁移**先后序未定义,而当前 orchestrator 的顺序会让后者失效**;测试计划里有一条钉住了与规则**相反**的行为。

---

## 问题

v11 把 lane 建成了一个**相位内**的概念:五个同相位词、三个跨相位词,`extends`/`narrows` 强制带 tag,一条边只有一个 tag 集合。三个后果:

1. **相位闸几乎什么也不拦。** 实测:「多相位 turn 任一配对合法」这个逃生口开着时,全库存活的人写边里**只有 1 条**不合法;关掉逃生口则 309/609(51%)不合法。**让图合法的是逃生口,不是相位轴。**
2. **跨 lane 的关系存不下来。** 单一 tag 集加上「tag 必须同时在两端节点上」,意味着一条从 lane A 指向 lane B 的边只能写成无 tag —— 它跨了哪两条 lane 这个事实丢失。
3. **一个词的 scope 与它的 tag 重复。** `ground → 同 lane` 与 `consume → 非同 lane` 只靠 scope 区分,而 scope 从两侧 tag 就能算出来 —— 这样的词携带零信息。

## 解法 —— 六个动作

1. **相位轴从关系词表中删除。** 词的含义与相位无关;`verify`/`override` 也不再要求引用方带取证 type。
2. **`refute` 并入 `override`**,词表从八个降到七个。
3. **一条边带两个 tag,每侧一个。** 弧尾 = 引用方所属 lane,弧头 = 被引用方所属 lane。多对多用多条边表达。
4. **归属来自节点自身的 tags**,不再从边推导。连通成员才需要两侧同 tag 的边。
5. **有边就必须有 lane**(结算完成后)。主 agent 写的边两侧 tag 同时暂缺 —— 那是**未结算**形态。
6. **scope 从七个词里搬到耦合规则里,只说一次。**

## 相对 v11 的变化清单

| v11 | v12 |
|---|---|
| 八词,分同相位/跨相位 | 七词,无相位约束 |
| `refute` 独立 | 并入 `override` |
| 无 tag 的 `override` = 全局否决(杀死节点) | **没有全局否决,没有节点死亡** |
| 带 tag 的 `override` 重开 lane | **没有重开机制** —— 最新成员不是 index 即 open |
| 一条边一个 tag 集合 | 每侧一个 tag |
| 成员资格由带 tag 的边推导 | 由节点自身 tags 决定 |
| `valid lane` | **删除**;质量信号并入连通性原则 |
| 单 source / 单 sink(E5,阻断提交) | **删除** |
| 自引:只允许裸 `ground` + 终点条件 | **一律不允许** |
| 判据含「周期较长」 | 只剩可分离、可持续 |
| `supersedes` 冻结但仍在 schema CHECK 中 | 机械迁移为无 tag 的 `override` |

## 实现决策

### D1 — 存储:边带两侧 tag

`memory_edges.tags`(JSON 数组)由两列取代:`tail_tag` / `head_tag`,各自可空。

**身份键是 `(citing, cited, relation, tail_tag, head_tag)`,而 SQLite 的 UNIQUE 不去重 NULL** —— 同一条未结算的关系可以重复插入,幂等性失效(今天 `tags='[]'` 恰好绕开了这个问题)。**决定:两列 `NOT NULL`,未结算用哨兵值 `''`(空串)**,而不是表达式索引或四个部分索引 —— 哨兵让唯一键、比较和索引都保持朴素,代价是每个读者都要知道「空串 = 未结算」这一条约定,写在列注释里。

`memory_edge_tags` 索引必须区分侧:`(edge_row_id, side, tag)`,主键 `(edge_row_id, side)`(每侧单值),二级索引 `(side, tag, edge_row_id)`。重建与迁移的测试必须断言**侧**,不能只断言边行。

**为什么不是「每侧一个集合」**:8.8%(41/464)的现存带 tag 边携带多个 tag,拆成多条边的迁移代价很低,而集合会把「同 lane」判定从一次相等变成集合求交,并重新引入 v11 那套 exact-set 比较的全部歧义。

### D2 — 写入闸

按侧检查,每条拒绝点名缺口:

1. **canonical form** —— 沿用 lane-declaration D1 的判据,拒绝而非静默规范化。
2. **该侧的 tag 已在该侧端点所属的段中声明。** 身份是 `(段, tag)`。**两侧 tag 字面相同但分属两个段,是一条合法的跨 lane 边**,按跨 lane 统计,不是拒绝对象。
3. **subset**:该侧的 tag 必须也在该侧端点节点自身的 tags 中。

**两侧要么都有 tag,要么都没有。** 只有一侧有 tag 的边被拒绝 —— 否则会产生一种既不进任何计算、又不进结算待办的半结算边。

**自引边一律拒绝**:一条边的两端必须是不同节点。迁移撤回全库唯一那条(`S15069/T1265 ground T1265`,跨相位年代的产物)。

### D3 — 声明

`declare` / `undeclare` 沿用 lane-declaration 票 01/02 已建的机械(canonical、与段策展 tag 防碰撞),三处改动:

- **允许 0/1 成员的 provisional lane。** 声明可以发生在第二个成员出现之前;**不规定固定时点**。连通性原则对 provisional lane 不适用。
- **`undeclare` 的守门条件从「仍有边携带该 tag」改为「仍有成员节点自身带该 tag」**。归属现在来自节点 tags,旧条件会让一条有成员、零边的 provisional lane 被撤掉,留下指向不存在 lane 的归属。撤回时要么原子地清掉全部成员的该 tag,要么在还有成员时拒绝 —— **决定:拒绝**,清理是结算的显式动作。
- 结算侧的 `remember` 门面已在票 02 中获得 `declare`/`undeclare`,不需要再动。

### D3b — tag 的命名空间与写入闸

`tags` 一个字段,两个封闭词表,按**写入者**分:

- **机器写的 tag 必须带前缀**(`compact:` / `invalidated:` / `delivery:`,由 hook 直接写库,不走 agent 的写入闸)。
- **注册的 lane tag 必须是裸词**。`checkCanonicalLaneTag` 增一条:含前缀分隔符的值拒绝声明。今天库里的前缀命名空间只有那三个(534 / 77 / 45 次),外加两条畸形的 `1:` —— 这条规则连它们一起挡住。
- **agent 能写进 `tags` 的,只有:该 turn 所属段已声明的 lane tag,以及该段的策展 tag。** 其余拒绝,拒绝信息列出当前合法集合。没有合适的就不写 —— `tags` 本来就是可选的。
- **不做成 schema 枚举。** MCP 的工具形状在连接时公布一次,而 lane 由结算中途声明、attach 也会中途变化,枚举当场过期。词表已经在段卡片的 lane 列表里注入给主 agent 了。
- 主 agent 与结算的 `.describe()` 各写一份 —— 两套注册早就存在,`recall`/`timeline` 共享描述、`note`/`remember` 分叉。

**遗留的 7694 个自由 tag 值不清除**,只禁新写。它们在归属计算里天然为零(未声明即非 lane)。段卡片的直方图会随时间从主题词漂向 lane 词,不做一次性手术。

**连带的风险与它的解法**:遗留裸 tag 一旦被声明为 lane,会**追溯征召**所有带它的 turn —— `spec` 153 个、`citation-edges` 124 个、`timeline` 123 个。判据(可分离/可持续)是防线,但那是纪律不是结构。因此 **`declare` 在声明前报出这个数**:「声明 `spec` 会让 153 个既有 turn 成为它的成员」。把隐患变成声明当下的知情决定,而且这个数本身就是「这个名字太泛」的最好证据。

### D3c — 主 agent 保留完整能力,靠描述而非阉割

`declare`/`undeclare` **留在主 agent 的 `remember` 上**。主 agent 也是用户的手:用户说「给 X 建一条 lane」,把他赶去结算(他无法直接驱动)更糟。改的是**描述与 rubric 的提示** —— 你不需要主动声明,这是结算的日常职责;你在这里是为了手动调整。

**主 agent 也写边的两侧 tag**,规则与 `tags` 完全一致:词表里有合适的就写,没有就留空。**两侧同时缺省是合法的草稿态**;写了但不在词表里,照样拒绝并列出合法集合。写入闸只拒绝「写的人拿手上的东西就能修好」的那两条(canonical 形式、subset),声明是否存在也在闸内 —— 卡片的 lane 列表已经注入给它了。

三种强度对三件事,不要混:

| 事 | 强度 |
|---|---|
| 主 agent 写 `tags` 与边的两侧 tag | **写入闸拒非词表值,允许缺省** —— 一条规则管两处 |
| 主动声明 lane | **描述与 rubric 提示**,可被用户覆盖 |

### D3d — 主 agent 与结算的职责,收到最窄

**主 agent 只写一个 turn 的五个字段**:title / content / insight / type / tags。边不归它写,段的归属也不需要它挂靠。

**结算只做两件事**:改 turn 的字段(含边),以及 lane tag 的 `declare` / `undeclare` / `merge`。

**注意一处措辞纠正**:「结算不碰段」是错的说法。**能改一个 turn 的 tags,本质上就是能改它的段归属** —— 归属由 tags 推导,所以两个写入者都保有这个能力,只是它从一个专用动词**搬进了 tags 字段**。退役的是 `reassign` 这个**动词**,不是这个**能力**。

支撑这次收窄的实测:**354 条 lane 内结构边里,326 条(92.1%)引用的是紧邻的前一个成员**,25 条 ≥4 节点的 lane 是纯链 —— 主 agent 写下的边大多是「上一轮」,而那是行序本来就有的事实。诚实的保留:该数据出自 mandate 时代,证明的是现行实践差,不是写入者不可教;取舍偏向收窄,是因为**结算随时可以少给,而坏习惯很难教回来**。

要认的代价:近期窗口在结算追上之前**没有图**(选举、lane 视图、卡片的 lane 行都读边);结算从纠错变成全部作者,窗口有界、远处的目标要靠 recall。

**退役的动词**:结算门面的 `propose`、`reassign`、`create` 一并退役 —— 段整块回到主 agent(创建)加自动挂靠(归属),结算不再碰段。**新增 `merge`**:把两条 lane tag 合并成一条,原子地改写全部成员 turn 的 tags 与全部边的两侧 tag,然后撤销被并的那条。半并的状态不允许存在。

### D3e — 段一个全局唯一 tag,归属自动推导

- **段以一个全局唯一的 tag 标识。** 实测这在活的容器上几乎是补齐而非收缩:九个 open 段里两个各带一个 tag、零冲突,其余七个一个都没有;29/21/18 个 tag 的怪物与全部全局冲突都在 delivered / closed 那批。迁移的形状是「给七个标准容器各起一个名字,清空已交付段的派生列表」。
- **归属由 tags 推导**:一个 turn 的 tags 里出现哪个段的 tag,它就属于哪个段。显式的 `note(segment=...)` 挂靠退役。
- **多匹配在定义上不可能**,并由写入闸保证:`tags` 里出现第二个段 tag 时拒绝,并点名冲突的两个段。
- **lane tag 需要它所属段的 tag 同时在场**:写一个 lane tag,而该 lane 所属段的 tag 不在这个 turn 的 tags 里,拒绝。于是「**无归属的 turn 不能进任何 lane**」是结构保证,不是纪律。

三条合起来是一组紧的不变式:`tags` 里至多一个段 tag;每个 lane tag 都必须匹配那个段;因此没有段 tag 就没有 lane tag。两种归属的操作形状也因此统一 —— **都是从一份词表里挑一个 tag**。

### D3g — 会话挂靠哪个段,交给人

turn 的归属自动推导了,但**会话**挂靠哪个段(决定注入哪几张卡片)在这次收窄后**没有主人**:主 agent 不再管段,结算也不管。

**做成 Claude Code 插件的一个菜单命令,由用户手动选。** 插件今天只有 hooks / scripts / skills 三个目录,没有 `commands/` —— 这是一处新增,但用的是插件本来就支持的形状。流程随之变得自洽:会话开始 → 只看到花名册(段词表)→ 用户选一个 → 卡片出现(当前段 tag + 段内 lane 词表)。

### D3f — 注入面收成五槽

八类注入块退役三类:

| 退役 | 理由 |
|---|---|
| `notes` | 内容按三分规则散进工具描述与字段 describe,一句不丢 |
| `proposals` | 它唯一的消费者是主 agent 采纳建段提案,而段已改为自动挂靠 —— 与 `propose` 动词一同退役 |
| `digest` | 规则不该注入在这里;自我演化之后会重构,不会沿用这套台账 |

留下:`sessions`(段花名册)、`segment<n>-milestones`、`segment<n>-fields`、`rubric`、`persona`。

**卡片的清理**:`- tags:` 与 `- type:` 两条直方图行删除 —— 它们渲染的是成员 turn 的历史分布,在新模型下**看起来像词表而实际不是**(能写的只有段 tag 与段内 lane)。腾出的预算归 `- lanes:` 行,而**段自己那一个 tag 移进卡片头**:挂靠之后它是 `tags` 的两个合法来源之一,现在却只在花名册里出现。

**留待裁决**:`propose_rule` 的写入侧仍然活着(dream agent 每晚可写),而它的注入出口刚被撤掉。台账最后一条写于 2026-08-08,59 条规则里 37 条停在 `digest_only`。撤了读侧不动写侧,等于养一条只写不读的通道。

### D4 — 迁移(一次,随发版)

**先后序,必须写死。** 当前 `initializeSchema` 先 `ensureMemoryEdgesSchema`(schema.ts:2630)、最后才 `runLaneRegistryMigration`(schema.ts:2687),而后者的 M0/M2 读的正是 `memory_edges.tags`。**若 v12 的 M-A 落在 `ensureMemoryEdgesSchema` 里,它会在旧迁移读之前删掉那一列,让整批 lane-declaration 迁移当场失效。** 因此:

- **升级库**:先完整跑完 lane-declaration 的 M0–M4 与它们的收据,**再**跑 v12 的 M-A~M-D;
- **全新库**:直接建成 v12 形状,旧迁移不运行,并在收据里显式标记「不适用」。

| 阶段 | 动作 |
|---|---|
| M-A | `tags` → `tail_tag` = `head_tag` = 原 tag;多 tag 的 41 条拆成多条边;`tags='[]'` → 两侧空串(**未结算**)。 |
| M-B | `refutes` → `override`;`supersedes` → 无 tag 的 `override`。 |
| M-C | 撤回唯一那条自引边。 |
| M-D | 删除 `supersedes` 的 schema CHECK 条目,以及 `segment-rank.ts` 里把它当 corrector / rolled-back 读的两处特判。 |

**M-B 在当前生产数据上已经撞键(实测)**:`S15069/T1072 → T1068` 这一对上同时存在 edge 2643(`refutes`,`asserted`)与 edge 3010(`override`,`judged`),两条都无 tag。M-A 之后两者的身份键完全相同,M-B 的 `refutes → override` 直接冲突。Rev 1 只核过 `supersedes` 的零冲突就推广到了整个 M-B,**那是错的**。

**冲突合并规则**:同一身份键上多行时,**保留 `asserted` 那行的审计元数据(id、created_at、provenance),删除 `judged` 重复行**,收据记下双方的行 id 与 provenance。若两行同为 asserted,保留较早那行。测试必须用这一对真实数据做夹具。

**M-A 的「无损」是对当前快照而言。** 现行唯一键允许同一 (pair, relation) 上同时存在 `{a}` 与 `{a,b}`,拆分后两者都产生 `(a,a)`。**生产上此形状为 0(实测)**,但迁移契约不能靠这个:同样走上面的合并规则,并把合并计数写进收据。「多 tag 边拆分后两侧一致」这条测试分辨不了这种情况,必须另加一条。

每个阶段的**数据与收据在同一个事务里**,并做 failpoint 重启测试 ——「有收据行 + 第二次是无操作」本身不证明崩溃安全。照搬 lane-declaration 的 `runWriteTransaction` 模式。

**迁移绝对不得把节点自身的历史 tags 自动声明为 lane。** `citation-edges` 这个 tag 有 **123 个 turn 自身带着它,却只出现在 2 个带 tag 边的端点上** —— 自动声明会立刻造出 121 个连通孤点。哪些 tag 成为 lane 是人工裁决。

### D5 — 选举:删除,加一次共享投影的替换

- **候选资格排除整条删除。** 全局否决没有了,这条规则失去依据。今天有 18 个存活 turn 靠它被排除,删除后它们重新入选。
- **共享的 lane 投影必须换,这不是 election redesign,但也不是「简化一个函数」。** v12 的成员资格来自节点自身 tags,而今天 `LaneTurnInput` 根本不带 tags,lane 成员只从带 tag 的边端点枚举(`lane-interpretation.ts:173-194,387-409,669-692`;`lane-checker-load.ts:166-209`)。反例:T1/T2 带 lane L 且 T2 index→T1,T3 也带 L 但还没有边 —— v12 说 L 是 open,现投影看不见 T3,仍判 closed。**loader 与 interpretation 的输出契约要一起改**,spec 把它算作一次替换而不是一次删除。
- **`deriveLaneStates` 简化**:closed = 最新成员发出一条弧尾为该 lane 的 index;否则 open。事件归约、`dead`、`lastDeclarer` 全部退役。
- **tier ② 由「closed-valid 终点」变为「closed 终点」**;`open-last-declarer` 这个席位随 `lastDeclarer` 一起消失,要有一条测试钉住它不再出现(`milestone-election.ts:309-321`)。
- **不做的事**:不重排层级、不调权重、不加新信号。

### D6 — 校验器:删除与重新瞄准

**删除**:E5(单 source / 单 sink,今天还在阻断提交)、报告 3(shared components)、报告 4a(inter-lane interfaces + bypass)—— 后两者追的都是 v11 已删掉的原则。报告 4c(时序违规)保留不动,它就是 DAG 保证。

**重新瞄准**:

- **连通性报告**:域改为「两侧 tag 同为该 lane 的边」;新增一行「closed lane 的终点是否被外部节点引用」。provisional lane 不报。
- **报告 4b**:改为在**段的全图**上做传递归约。**它的输出叫「结构性旁路候选」,不叫「冗余边」** —— 报告同时列出直接边与替代路径,**不指定该删哪一条**。rubric 的三种处置(删直接边 / 删绕行 / 两条都留)取决于「B 和 C 各自提供了什么信息」,那是内容事实,校验器手里没有。

**三份工件,不是一份切两半:**

## 测试决策

按外部可见的拒绝与渲染断言,不断言内部调用。

- **写入闸**:三条按侧的拒绝各一条;**两侧 tag 字面相同但分属两段的边被接受**,并按跨 lane 统计(Rev 1 这条钉反了);只有一侧有 tag 的边被拒绝;两侧都无 tag 的边被接受;自引边被拒绝。
- **身份与幂等**:同一条完全未结算的边重复写入只留一行;同一 (pair, relation) 上不同两侧 tag 组合是不同的行。
- **迁移**:用 `S15069/T1072 → T1068` 这对真实数据做 M-B 撞键夹具,断言合并后保留 asserted 行且收据记下双方;M-A 的多 tag 拆分产生撞键时同样合并;每个阶段的 failpoint 重启后状态一致;侧索引重建断言侧;第二次运行是无操作。
- **选举**:候选资格排除删除后原先被排除的节点重新进入;**只带 tag、还没有边的成员参与 closed/open 判定**;`open-last-declarer` 席位不再出现。
- **校验器**:E5、报告 3、报告 4a 的消失各有一条 grep 哨兵;连通性新增那行在两侧各一条;耦合三组计数在一个三 lane 夹具上精确;4b 的输出同时含直接边与替代路径且不指定删哪条。
- **rubric**:共享半的字节一致性;结算半只出现在结算提示词里;两半合起来覆盖模型的每一节。
- **两侧门面**:主 agent 的 `note` 拒绝任何带 tag 的关系条目(形状层面拒绝,不是运行时校验);结算的门面接受两侧形式。
- **控制台**:载荷不再含 `validity` / `lastDeclarer` / `dead`。

**平台地雷,写迁移前必读**:`bun:sqlite` 的**多语句 `db.exec` 会吞掉某条语句的约束失败,并继续跑完剩下的**。实测:三条 INSERT、中间那条违反 CHECK,`exec` 不抛异常,坏行静默消失,第三行照常写入。**任何用多语句 `exec` 搬数据的迁移都会无声丢行** —— 一律走预备语句的 `.run()`。库里现存的三处多语句 `exec` 都是 DDL(`IF NOT EXISTS`),但值得单独扫一次。

**每一条声明为承重的性质都要突变验证**:破坏它,点名变红的测试,再还原。存活的突变是发现,补测试再收工。

## 验证:怎样知道这套定义能不能 work

**Rev 1 的验证计划不能判因** —— 报告读起来是噪声至少有三种来源:定义错、lane 挂靠错、边的两侧 tag 补得不全。所以先出**控制量**,再出报告。

**第一步:迁移。** 迁移后的基线不是「全库同 lane」(Rev 1 这句是错的):旧的 `tags=[]` 只能映射成两侧空串,即**未结算**,完全不参与 lane 计算。真实基线是「所有非空旧 tag 行内部化为同 lane;所有旧无 tag 行进入待挂靠队列」。

**第二步:挂靠,并用控制量判定它做完了没有。**

| 控制量 | 目标 |
|---|---|
| 任一侧为空串的边数 | 0 |
| 每条已结算边的声明/subset 违规数 | 0 |
| 有边但两端都无任何已声明 lane 的节点数 | 0 |
| 人工金标样本(按关系词与段分层)上的两侧 tag 准确率 | 报告出来,不设阈值 |

**第三步:出报告,每条 finding 都带来源地址与两侧 LaneKey。**

**第四步:判因。** 先人工判「这条 finding 的挂靠对不对」,再判定义:

- 挂靠错 → 修标注,重跑;
- **挂靠对而耦合/连通仍误报 → 定义错。**

「closed lane 的终点无人引用」这一类还有第三种可能:**引用边根本没写**。对这批样本必须去下游 turn 的内容里检索一遍,确认外面是不是真的提到了它 —— 不能直接据此裁掉连通性那句。

**基线数字(只读实测,发版前)**:存活 turn 10334;asserted 人写边 609,其中 600 条段内、0 条跨段;asserted 边端点 550 个,已有 lane 的 224 个,待挂靠 326 个(305 个在 E60);派生 lane 99 条,closed 54 条,其中终点被外部引用 32 条;lane 成员数中位 3、跨度中位 7.5、内聚中位 61%;跨 lane 边 前四 3 / ground 15 / consume+index 12;传递归约可删边 全图 27/484、lane 内 13/354;E60 有 1537 个存活成员、75 个边 tag,比例告警配额 76.85,**还剩两条 lane 的余量**。
