## Report (landed)

**The ticket's own reproduction does not hold today.** `sqlite3 -readonly ~/.claude-mnemo/claude-mnemo.db "select count(*) from shadow_notes where writer_model = ''"` returns **0**, not 353 (3306 rows total: 346 `NULL`, 2960 real model strings; confirmed with `typeof()`/`length()` to rule out a NULL-rendered-as-blank illusion in the `sqlite3` CLI — the exact trap I fell into once myself mid-investigation). No commit in this file's history (`git log -p --all -- src/mcp/note.ts src/db/shadow-notes.ts src/hooks/backfill.ts`), no cached prior release (checked 0.28.0 and 0.29.0's built `.cjs`), and no code path in the current tree ever writes a literal `''` — `resolveWriterModel` (`src/mcp/note.ts:340-350`) and every `upsertShadowNote`/`upsertReconstructedShadowNote` call (`src/db/shadow-notes.ts`, `src/worker/note-settlement-turn-facade.ts:1996-2010`) coalesce with `?? null`, and `backfillShadowNoteWriterModels` (`src/hooks/backfill.ts`, pre-fix) only ever writes a *truthy* `assistantModel`. The peer's own "空串" (empty string) almost certainly described the same blank-cell illusion, not a byte-level `''` — the `note` tool result's "no `writer_model:` field" observation is exactly what NULL produces (`note.ts:1504-1505` prints the line only `if (writerModel !== null)`), which is consistent with a normal, expected miss at write time (Claude Code never exposes a model identity to an MCP server — comment at `transcript-parser.ts:22-26` — every note is written with `writer_model` NULL and depends entirely on the Stop-hook backfill to recover it).

**The real, currently-reproducible defect (root cause, file:line):** `backfillShadowNoteWriterModels` (`src/hooks/backfill.ts:54-72`, pre-fix) matches each parsed-transcript turn to a DB turn by `content_prompt_id` first, falling back to `prompt_number` (`byPromptId ?? byPromptNumber`). A DB turn ends up with `content_prompt_id IS NULL` forever when it was never the *latest pending* turn at the moment its own Stop cycle ran — `backfillFromTranscript` (`src/hooks/backfill.ts:109-139`, unchanged, and correctly conservative) captures `content_prompt_id` *only* for `isLatestPendingTurn`, deliberately, because a positional match for an older turn is unsound once transcript/DB turn-numbering has drifted anywhere earlier in a long session. Once such a turn exists, `backfillShadowNoteWriterModels`'s promptNumber fallback can never reach it: whichever transcript entry happens to sit at that turn's own `prompt_number` almost always carries its OWN `promptId`, which wins the `??` and diverts the match to a different, correctly-addressed DB row before the promptNumber fallback is ever tried for that position — so the orphaned turn's `prompt_number` is never actually queried by anything. **Verified against live production**: `SELECT ... FROM shadow_notes n JOIN turns rt ON rt.id=n.ride_turn_id JOIN sessions s ON s.id=rt.session_id WHERE n.writer_model IS NULL AND s.completed_at_epoch IS NOT NULL` (i.e. rows whose ride session has already run Stop many times since — every chance to backfill, permanently unfilled) returns exactly 5 rows; all 5 ride on turns whose `user_prompt` begins `<cross-session-message from="uds:/tmp/cc-socks/...">` and whose `content_prompt_id` is NULL. A throwaway probe running the ACTUAL `parseReplayTranscript`/matching logic (read-only, against the real prod DB and the real transcript file, never writing) confirmed zero transcript-parsed turns ever resolve to one of these rows via the existing promptId/promptNumber matcher — exactly the mechanism above, not a guess.

**Fix** (`src/hooks/backfill.ts`): added `backfillOrphanedRideTurns`, called after the existing loop. For ride turns still missing `writer_model` whose own `content_prompt_id IS NULL` (so promptId correlation is categorically unavailable, and the promptNumber fallback is unsound — see above), it correlates by the one thing a synthetic delivery still shares verbatim with its transcript echo: `turns.user_prompt` as a substring of a parsed turn's `userPrompt` (Claude Code prefixes the echo, e.g. `"Another Claude session sent a message:\n"`, but never rewrites the payload). Anchor length is bounded to 200 chars — long enough to carry a cross-session message's unique socket path, short enough that the harmless prefix never eats the whole anchor. `writer_model` was chosen as the field to relax matching confidence on deliberately: unlike `content_prompt_id`, nothing downstream keys off it as a correlator — it is P1 measurement metadata (`src/metrics/p1/*`) — so a lower-confidence, best-effort recovery here is a sound, narrowly-scoped trade that leaves the `content_prompt_id` capture design (and every one of its other readers) untouched.

**Backfill decision for legacy rows: none needed, stated with a receipt.** Production currently holds 0 rows with `writer_model = ''` (see above) and only 5 rows with the *class* of defect this fix targets (permanently-orphaned `content_prompt_id`), all sharing one root turn (`turns.id=13386`, ride turns `13375/13377/13381/13384` in session 15069) plus one more in session 18993 (`turns.id=11839`, ride turn `11836`) — all cross-session-message deliveries. This fix is forward-looking (the *code path*, not a migration) and does not retroactively touch `~/.claude-mnemo/` (read-only per constraint); the 5 existing NULL rows will self-heal the next time their owning session's Stop hook runs the new code (each session is still active), which requires no separate backfill script. No row anywhere in the corpus needs an *empty-string* correction because none exists.

**Tests** (`tests/hooks/note-debt-capture.test.ts`): added `addTurn`'s optional `contentPromptId` param (default `null`, matching every existing call site's prior implicit behavior — the column was never set by that helper before). Two new tests: (1) an end-to-end Stop-handler drive of the exact orphaned/position-stolen scenario (a `content_prompt_id`-less ride turn whose own numeric position is claimed by a different turn's real promptId — mirrors the production shape byte-for-byte down to the `"Another Claude session sent a message:\n<cross-session-message ...>"` wrapper), asserting the note recovers the CORRECT model (`claude-opus-9`, from the true echo) and not the model that happens to sit at the stolen position (`claude-sonnet-5`); (2) a guard test that the fallback leaves `writer_model` NULL (no throw, `filled === 0`) when nothing in the transcript ever carries the payload. All 5 tests in the file pass; full suite **4819 pass / 0 fail / 266 files** (baseline was 4817/0/266 — the +2 is exactly these two tests, nothing else moved).
