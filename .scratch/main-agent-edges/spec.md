# Edges are node facts; lanes are attributions — derived when unique, declared only when ambiguous

**Status:** READY FOR IMPLEMENTATION at Rev 10 (user ruling S15069/T2431: "不采用 fork,先进入实现"). Invariants frozen; the peer's round-9 and round-10 executability lists are attached verbatim as `acceptance-matrix.md` and every ticket must dispose of each applicable line in its report. The fork-writes-notes experiment (peer, T2430) found the mechanism cache-identical and identity-preserving but 4.7× the cost of inline notes with no context saved — not adopted; D3 stands as written. ## Problem Statement

Edge-writing moved wholly to settlement on 2026-08-25 (T1651). Since then v13 gave three classes; lanes became settlement-only; and settlement's edges cite the immediately previous turn 47.9% against the main agent era's 37.7% (production, 2026-09-02) — hindsight bought no range, while the edge pass is 81% of settlement cost.

The lane sides stored on edges carry almost no information. Production, read-only: 87% of laned turns are in exactly one lane; 69% of edges have both endpoints uniquely laned, 22% have an ambiguous endpoint, 10% a lane-less one; on every placed edge whose endpoint has one lane, the stored side equals that lane (2,660/2,660 tail, 2,686/2,686 head). Legacy stock that does not fit the new model: 109 pairs stored as several physical rows; stored declarations on uniquely-laned endpoints (redundant by the figure above); any endpoint with malformed tags; any declaration no longer among its endpoint's tags.

## Solution

**An edge is a fact about two nodes: citing, cited, class, coverage.** Both writers write exactly that; the main agent on its own turn's `note`, without lane sides. **A lane side is an attribution**: resolved at read time as declared → unique → none; **settlement declares a side only where the endpoint is in several lanes**. **Legacy rows are made to fit at cutover, once**: multi-row pairs fold to one row, redundant and invalid declarations are cleared, malformed tags are normalised — with a receipt table that can restore every changed row. No read-time projection, no second address form, no grandfathering.

Node readers consume every valid node fact; lane readers consume only sides that resolve to their qualified lane. Settlement's edge pass becomes **declare → fill → review**.

## User Stories

1. As the main agent, I want to record in this turn's `note` which earlier turns this turn used, corrected (full/partial) or verified, without caring which lane any of them is in.
2. As the main agent, I want my first edge on a turn with no outgoing relation atoms accepted without a relations read.
3. As the settlement writer, I want to declare an ambiguous side on the SAME edge — same row, same provenance, same class.
4. As the settlement writer, I want the commit gate to name exactly the edges whose ambiguous side I left undeclared, and the edges whose declaration no longer matches its endpoint's tags — nothing else.
5. As a lane reader, I want an edge's lane resolved by one rule, so that 69% of edges join their lanes with no writer having said so.
6. As a node reader, I want every valid node fact counted whether or not it resolves to a lane.
7. As a reader of the `relations` field, I want each side marked declared / derived / ambiguous / none / invalid.
8. As the user, I want the 20-out / 20-in caps and the class precedence to hold mechanically for both writers.
9. As the user, I want both writers' edges measured apart by provenance.
10. As the user, I want the legacy stock folded and cleared ONCE at cutover, with a receipt I can roll back, rather than carried by machinery forever.

## Implementation Decisions

### D1. Storage: edges only, class is the relation, `relation` word column dropped, `(citing, cited)` unique

After the cutover `memory_edges` holds RELATION FACTS only: `relation_class` NOT NULL (`correct|verify|use`), `relation_coverage` (`full|partial` for correct, `''` otherwise), `tail_tag`/`head_tag` (`''` = undeclared), provenance, timestamps; `(citing_kind, citing_id, cited_kind, cited_id)` is the UNIQUE key. **The seven-word `relation` column is DROPPED in the rebuild** — the interim word fill, every raw-word reader and the `relation IS NULL` discriminator go with it; there is nothing left for `indexes` to be preserved in. **Every wordless row is DELETED at cutover (T2419/T2421):** 1,883 today — 1,187 `text-ref` prose references and 696 `judged` bare pair-existence records (`schema.ts` ~4362–4395). No replacement table: a typed identity table would have to reproduce the kindful session/segment/turn endpoint space (`db/citations.ts` ~546–573) for a fact nobody acts on. Readers affected and dispositioned: the `note` receipt's "Cites N pair(s)" line — deleted; the "mentioned in prose but never cited" lint — recomputed from the prose at check time (a regex over `content` for `S<n>/T<m>` addresses) or deleted with the sentence, ticket 1 decides by call-site sweep; the bare-pair index and the bare-row write path in `attachTurnRelations`/`writeMemoryEdges` — deleted. The wordless domain is in the receipt and inside the rollback fence like every other edge row. A stored side tag means exactly "this endpoint is in several lanes and this is the one"; it must be one of the endpoint's own lane tags in its task. `memory_edge_side_tags` indexes explicit declarations only.

### D2. Resolution: five outcomes, one pure function, endpoint facts loaded once, candidates per reader

`resolveEdgeSide(edge, side, endpointLaneFacts)` is pure: `declared` (stored tag among the endpoint's current lane tags); `derived` (no stored tag; exactly one lane); `ambiguous` (no stored tag; two or more); `none` (no stored tag; no lane); `invalid` (stored tag not among the endpoint's current tags — E4's fact). `invalid` never falls back to `derived`. Lanes are qualified `(segmentId, tag)`. There is no `unknown`: malformed endpoint tags are normalised at cutover (D9) and refused at write.

`loadEndpointLaneFacts(db, turnIds)` (owning task, qualified lane tags) is the one shared piece; each reader keeps its own candidate scope and projects through the resolver — the direct renderer: all rows incident to the node; lane readers: rows incident to the lane's members (today's loaders require a STORED side — `db/lane-checker-load.ts` ~521–584, `mcp/timeline.ts` ~4848–4868 — the predicate becomes "incident to a member"); the audit: outgoing rows of writable citers; phase connectivity: BFS over node facts.

**Node readers, by predicate:** global election and in-degree, time-order/bypass, citedness, phase connectivity (its loader drops the both-sides-non-empty SQL filter, `db/basis-reachability-load.ts` ~108–147; test: an undeclared unique-endpoint edge carries the BFS), storage, retraction, and the direct renderer (reads every incident node fact, then annotates sides). **Lane readers:** lane views, frontier digest and SessionStart roster, lane-checker coupling, lane impressions' member edges, `emptyLaneTags` (uses resolved attribution, not the declaration index). **Milestone election becomes a heuristic score (RULED, T2421), specified:**

- **Pool and K, per route** (HEAD's `selectMilestoneTurns` is a session/window selector that no longer cuts, and the E-view and S-view are cut by different token fitters, `mcp/timeline.ts` ~1557–1684, ~3819–3915): the **pool** is exactly the unit set each route feeds its fitter today (E-view: era-visible member turns of the segment/lane; S-view: the session window's turns), invalid nodes excluded as today; **scoring happens where the retired election ranked** — it produces the candidate ORDER handed to that route's existing token fitter; **K** is whatever the fitter admits in score order under its budget (no fixed 25); at a tied cutoff the tie tuple below decides — no partial admission. Display order stays chronological.
- **Score** of node n: `S(n) = w_out · outDeg(n) + Σ_{e ∈ out(n)} w_class(e) + w_rec · rec(n) + w_type · type(n)` where `outDeg` counts n's logical edges; `w_class(e)` = `correct/full` 2.0, `correct/partial` 1.5, `verify` 1.0, `use` 0.5; `rec(n) = 1 − rank_age(n)/|pool|` (rank by event order, newest = 1); `type(n)` = the max over n's types of a per-type weight (design, correction 1.5; measure, research, review 1.0; implement, fix, refactor 0.5; ops, delegate, discuss 0.25; none 0); `w_out = 1, w_rec = 1, w_type = 1`. All weights in ONE table (`election-weights.ts`), named as a tuning knob and adjusted only by looking at production.
- **Ties:** score desc, event order desc, row id desc — deterministic.
- **Every raw-word consumer, dispositioned (exhaustive; ticket 2 proves it by grep of the seven words over `src/`):** the tiered election and its in-degree word table — DELETED; `edge-signals.ts` — DELETED (no caller); too-fine-index warning (`shared/lane-checker.ts` ~1418–1435) — DELETED; lane stats by word (~944–967) — by class; the segment-graph word set and cross-phase citedness (~334–354) — by class (any relation counts); grounds / consume / testimony buckets (`db/lane-checker-load.ts` ~425–427, ~1360–1434) — DELETED: the grounds-vs-consume distinction does not exist in three classes and no report that splits them survives; coupling groups (~1642–1661) — by class; frontier SQL, model and branch/mirror ranking (`mcp/timeline.ts` ~4716–4723, ~4831–4890, ~5833–5861) — by class and coverage; "latest override" (~5332–5346) — becomes latest `correct/full`; relation-tree rank (`mcp/relation-tree.ts` ~56–63) — explicit order `correct/full > correct/partial > verify > use`; impression lane touches — unchanged (they read tags, not words). D9's text that said promotion updates "class + coverage + word" was stale and is gone: there is no word column. v13 05a/05b are CLOSED; the election's before/after diff on the clone is an EXPECTED change, listed, never an equivalence.

**Lane lifecycle mutates attribution, never node facts — and every attribution-changing verb POST-NORMALISES.** After any change to an endpoint's lane set (lane clear / merge / retag, membership add or remove, task move), the verb re-resolves EVERY incident side of that endpoint in the same transaction and applies one rule: cardinality now < 2 → any stored declaration is cleared (so "stored means several lanes" stays true — the alpha+beta edge that declared alpha becomes `derived` when beta goes, never a stale `declared`); a declaration no longer among the endpoint's tags → cleared; the result `ambiguous` (cardinality ≥ 2, no valid declaration) → if a settlement job over a window containing the CITER is live it is invalidated (D9) and stage 2 declares; otherwise the edge is DELETED, receipted, reported (T2421). `clearLane` therefore no longer deletes relation rows or restores bare ones (`db/lanes.ts` ~993–1155). Verbs also snapshot each incident edge's OLD and NEW qualified resolutions and persist BOTH lane keys as touches (the `E1/#alpha` → `E2/#alpha` case leaves old `E1/#alpha` owed).

### D3. What the main agent writes; the gate exception

Bare-address `correct` (+`coverage`), `verify`, `use` entries on its own turn's `note`; the public `note` gets its own entry shape (address only) split from the shared `relationTargetEntryShape` so settlement keeps two-sided entries. Rubric main-agent half, two sentences: what this turn used, corrected or verified — the cited turn's principal result, not a detail; correct > verify > use; one edge per pair; the caps. Gate exception, writer-agnostic: inside the write transaction, before the receipt lookup, a citing turn with zero outgoing RELATION atoms (bare prose rows do not count) skips the relations-read requirement; every other guard and the caps still apply. Lands as a read-once ticket 00 addendum.

**What the relations grant covers:** node rows only — the citing turn's outgoing relation rows (T2393, T2404). Rendered attribution marks are not covered; the authority for a declaration is the post-stage-1 endpoint facts inside the finalize snapshot (D6), never a renderer mark.

### D4. Declaration is an in-place update of the logical edge

`declareEdgeSides((citing, cited, class), patch)`: after cutover every pair has ONE row, so the logical address always matches exactly one; updated in place — row id, class/coverage, provenance, created time preserved. Patch per side: omitted = unchanged; a string = set (validated against the endpoint's current qualified lane tags, else refused as `invalid-declaration`; **refused by name when the endpoint's lane cardinality is < 2 — "derivable; no declaration needed"**); explicit `null` = clear to `''`. Side effects in one transaction: side index updated; citing turn's relations revision stamped once per changing call; lane touches persisted for old and new qualified lanes. Retraction addresses the logical edge and resolves the class through the MATERIALIZED class, never the physical word.

### D5. One pair, one row; precedence and coverage mechanical

Row identity is the logical edge `(citing, cited)`. In `attachTurnRelations`: several classes on one pair in one call → the most specific is stored; `correct(full)` and `correct(partial)` on one pair in one call → the whole call refuses naming the pair; a later STRONGER class or a coverage change → in-place UPDATE of `relation_class` and `relation_coverage` (there is no word column), provenance preserved, one stamp; a later WEAKER class → no-op, no stamp; a second side placement → never a new row. The 20/20 caps count logical edges. No legacy branch exists after cutover (D9).

### D6. Settlement's edge pass: declare, fill, review; findings; derived closure

(1) DECLARE every side in the audit scope that resolves `ambiguous`; clear or re-set every `invalid` one. (2) FILL edges the main agent missed. (3) REVIEW: retract wrong edges, `lane_check`, debts, impressions, commit.

**Audit scope keeps its three layers** (`note-settlement-sdk-query.ts` ~968–1068): load CONTEXT, ADMIT a finding only when its citing anchor is in the judgment set or authored by this run, PROJECT to writable authority; actionable rows are the OUTGOING rows of writable citers; preview and commit share the predicate. **Findings:** E6 = a blank side whose endpoint has ≥2 lanes; E4 = `invalid-declaration`; a blank side on a unique or lane-less endpoint is never a finding.

**Derived removed-side closure.** Inside the finalize transition transaction, after all stage-1 writes: for every endpoint whose lane facts changed, compare the PRE and POST resolution of each incident relation row; any outgoing row whose post-side is `ambiguous` or `invalid` contributes its citer to the writable set with a persisted provenance `derived-side-citer`. Executable form: the PRE resolution of every incident side is recorded IN the attribution-mutation transaction (stage 1's batch tag write and every structural verb write the affected turns' pre lane facts to the job's transition scratch — HEAD keeps only limited pre-tags, `db/note-settlement-snapshots.ts` ~52–106, ~133–144); the closure is computed at finalize against POST facts; `derived-side-citer` is added to the provenance schema and to the permission union as RELATIONS-ONLY, exactly like `removed-side-citer` (the closed union today grants fields to every other provenance, `note-settlement-sdk-query.ts` ~2833–2840, ~3373–3419; `note-settlement-turn-facade.ts` ~1362–1397); the FINAL union is written atomically before stage 2 and the prompt, the range gate, `lane_check` and `commit` read that one snapshot; stage 2 declares or deletes each such edge. Tests cover the ambiguous and the invalid path. Lane verbs run outside settlement do not record debt: they invalidate overlapping jobs or delete (D9).

### D7. What stays with settlement

Lane declaration and tagging, topic determination, the audit of title/type/tags, impressions, handover debts, ambiguous-side declarations, invalid-declaration repair.

### D8. Measurement — by provenance

For the first N windows: edges per window by provenance; previous-turn share and mean gap by provenance (baseline settlement 47.9%, main agent era 37.7%); attribution outcomes per side; E6/E4 counts; settlement round trips and dollars per window against the 0.29.0 baseline ($3.45 edge pass). Success stated up front: edge-pass cost falls; previous-turn share ≤ 48%; ambiguous and invalid at commit both 0.

### D9. Cutover: the legacy stock is made to fit, once, in one transaction, with a complete receipt (RULED, T2419 + T2421)

One receipt-guarded one-shot in `initializeSchema`, all of it inside ONE `runWriteTransaction` (foreign-key pragma handled outside if needed): guard check → receipts → the transforms → the table rebuilds → `PRAGMA foreign_key_check` and an exact side-index verification → the completion marker, written LAST in the same transaction. A crash rolls back automatically. **Fail closed on a DURABLE fence every initializer reads.** Hooks, the MCP server and the worker each run `initializeSchema` independently (`hooks/hook-command.ts` ~120–132; `mcp/server.ts` ~184–203; `worker/server.ts` ~1792), so the gate cannot live in the worker's process state. It lives in the database: the migration runs, in whichever initializer opens first, ONLY when no `note_settlement_jobs` row has status `claimed` — the claim rows are durable and visible to every process, and an in-flight settlement child holds one until it completes or its 10-minute lease expires. Child liveness is therefore irrelevant to the proof: a child without a claim cannot write (its writes are claim-fenced), and a child whose claim is live blocks the migration. While the fence blocks, every initializer proceeds on the OLD schema (no migration, no refusal of ordinary reads/writes) and the new worker refuses to claim new settlement work; the next open retries. Once the receipt exists, every initializer sees the new schema. It ships in the SAME release as every new writer and reader (tickets 2–7 must be present in the binary before the migration is enabled); ticket 1 may be implemented first but never released alone.

**Receipt = enough to rebuild the old state, every derived domain classified:** RECEIPTED (old bytes copied): `turns.tags` of normalised turns, `segment_members` rows of those turns, every old `memory_edges` row (all columns, wordless rows included), the write-gate field stamps of every touched turn, the old table/index/trigger DDL and the `sqlite_sequence` values. DETERMINISTICALLY REBUILT after a restore (never receipted): segment facets and derived type, the FTS rows of touched turns/segments, `memory_edge_side_tags`, the milestone/frontier caches. Nothing else is touched by the cutover. **Rollback boundary:** the cutover records the write-gate sequence at which it ran; a rollback is allowed only OFFLINE and only while NO write has touched a receipt-owned domain since that sequence — relation rows, `turns.tags`, `segment_members` — otherwise it refuses, because restoring old rows would overwrite later writes. Nothing weaker counts as reversible.

Transforms, in order:

1. **Normalise endpoint tags** by a migration-specific RAW update: NULL → `[]`; any value that is not a JSON array → `[]`; an array with non-string members keeps its string members and drops the rest (`["alpha",7]` → `["alpha"]`); both counts reported; then reconcile membership and facets for those turns. From then on the invariant is DB-level and complete: `turns.tags` becomes NOT NULL DEFAULT `'[]'`, and a BEFORE INSERT/UPDATE trigger raises unless `json_valid(tags) AND json_type(tags) = 'array' AND NOT EXISTS (SELECT 1 FROM json_each(tags) WHERE type <> 'text')` (a CHECK cannot contain a subquery; a trigger can). ONE parser (`readTurnTags`) is used by every reader and writer and throws a named `MalformedTurnTagsError` instead of coercing (`db/turns.ts` ~120–140, `db/segments.ts` ~211–240, ~1345–1359, `db/lanes.ts` ~627–647 today disagree).
2. **Fold multi-row pairs** (109 today) deterministically: per `(citing, cited)`, a relation row WINS over a bare prose row (the bare row is deleted, D1); class = most specific across the relation rows, coverage = (any full → full, else partial) only when class is `correct`; among rows carrying that class/coverage keep the LOWEST row id (its provenance and created time survive); a side keeps a declaration only if exactly one DISTINCT valid qualified declaration exists across the folded rows (identical duplicates are one declaration, not ambiguity); other rows deleted into the receipt. Nothing from `indexes` is preserved: the word column is dropped and no reader keys on it (D1, D2).
3. **Clear redundant declarations**: every stored side whose endpoint has exactly one lane → `''`.
4. **Clear invalid declarations**: every stored side not among its endpoint's current lane tags → `''`.
5. **Delete what cannot be attributed (RULED, T2421):** after 2–4, any surviving logical edge with a side that resolves `ambiguous` (blank, endpoint in ≥2 lanes, no declaration survived) is DELETED into the receipt and counted. There is no debt, no later repair branch: the postcondition is one row per pair, no E4, no E6.
6. **Rebuild `memory_edges` with `(citing, cited)` as the UNIQUE key and WITHOUT the `relation` column** (today's DDL and `ON CONFLICT` key `(pair, relation, tail, head)`, `schema.ts` ~1603–1608, `memory-edges.ts` ~539–553, so any writer could recreate multi-row stock; the bare-pair index ~1644–1680 goes with the bare rows), recreating the prune trigger and the side index from the surviving declarations; rebuild `turns` with the tags CHECK; `foreign_key_check` clean; side index verified row-for-row against the surviving declarations.

Report on the production clone: counts per step (normalised turns, folded rows, cleared redundant, cleared invalid, DELETED ambiguous edges), receipt size, and the before/after diff of every node reader and every lane view, with each difference classified as EXPECTED (degree collapses from the fold; edges deleted in step 5; election ranking under the new heuristic; lane views gaining derived edges the old loaders dropped) or as a defect.

**Concurrency with settlement — structural invalidation, one operation.** A structural lane or membership verb that alters attribution calls `invalidateOverlappingSettlementJobs(turnIds)`: for every `note_settlement_jobs` row with status `pending` or `claimed` (the real vocabulary: `pending|claimed|done|failed|abandoned`, stage separate) whose window/writable/frozen set intersects — INCLUDING a pending job that kept `stage='edges'` and its snapshots after a lease loss (`note-settlement.ts` ~1698–1717, ~1771–1786) — in one transaction: increment the claim generation, set status pending, set stage topics, delete its transition snapshots, worklists, debts and pending impression decisions, and arm cancellation for BOTH dispatch shapes; `done`, `failed` and `abandoned` rows are untouched (the verb deletes the unattributable edge instead) (the unified run's generation monitor and the cold edges dispatch, which lacks one today — `note-settlement-dispatch.ts` ~435–652 vs ~728–783; ordinary reclaim preserves `stage='edges'` and the frozen snapshot, `note-settlement.ts` ~1711–1717, which is exactly what must NOT happen here). For a DONE window, or when no live job exists, nothing is queued: an edge the change made unattributable (ambiguous side, no declaration) is DELETED by the verb itself, receipted, and reported — the same subtraction as the cutover (T2421).
