# 01 — 逐字段提醒的选取与文本(纯函数)

**What to build:** 给定「每个字段各自欠了多少轮」,得到**该提醒哪一个字段**,以及**那条提醒的完整文本**——
文本里自带「什么情况该写这个字段」的判据,不转发给别的文档。

本票**完全不碰数据库,也不碰任何现有文件**:新建一个模块,输入是一个普通结构,输出是一个字符串或 null。
读取真实时间戳、把它接进 `remember` 与 hook,是票 02 的事。

对应 spec:`.scratch/memory-guidance/spec.md` D2 / D3 / D4。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 输入形如「字段 → 距上次写入的轮数」,输出「选中的字段 + 文本」或「无需提醒」
- [ ] **三档间隔**(D2):`next_steps`/`constraints`/`decisions` = 20;`done`/`content`/`insight` = 60;
      `reference`/`goal` = 120
- [ ] **一次只选一个**(D4):多个字段同时到期时,按 高频 → 中频 → 低频 取,同档内取超期最多的那个
- [ ] **每个字段有自己的「什么时候该写」一句**,写进文本。`constraints` 那条必须带三行分流判据:
      会在这个项目里再次成立 → constraints;只对当前任务成立 → decisions;只对这一轮成立 →
      留在该轮的 insight,不要上搬
- [ ] 从未写过的字段按「欠得最久」处理,不是按零处理
- [ ] 纯函数:不 import 数据库,不读时钟——轮数由调用方给

## 必须钉住的,以及为什么

- [ ] **分级真的分级**:构造 `goal` 欠 100 轮、`next_steps` 欠 20 轮,断言选中的是 `next_steps`。
      两档若实现成同一个数,这条会红
- [ ] **一次只出一个**:让**六个字段同时到期**,断言输出恰好一条。
      ⚠️ fixture 里只有一个字段到期的话,任何针对「只选一个」的突变都是空的
- [ ] **判据文本随字段变**:断言 `constraints` 的文本含分流三行、`goal` 的不含。
      断言的是**这一个字段的文本**,不是「输出里包含某个词」
- [ ] 突变:把三档数字改成同一个;去掉「只选一个」;拿掉分流三行 —— 各自指出哪个测试变红
