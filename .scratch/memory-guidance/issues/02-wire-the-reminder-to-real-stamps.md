# 02 — 把提醒接到真实的逐字段时间戳上

**What to build:** 提醒真的按**每个字段各自**的沉默轮数触发,而不是今天那个「任何字段被写过就全部重置」的
全局计时器。

对应 spec:D1 / D5。

**Blocked by:** 01(纯选取函数)

**Status:** ready-for-agent

- [ ] 轮数读 `write_gate_stamps`——主键已经是 `(entity_type, entity_id, field)`,**不加新列、不加新表**
- [ ] **一次写入只重置它自己那个字段**的计数。写了 `next_steps` 不得把 `constraints` 的欠账一起抹掉 ——
      这是本票的要害,也是最容易实现成「全部重置」的地方
- [ ] `remember` 写入后回执里的那句维护提示,改成选中字段的那一条
- [ ] **裁决 D5:全局的 `sessions.last_remember_turn_id` 通道留还是退役。**
      倾向退役(两套计数 = 两条提醒在同一个注入槽里互相稀释),但必须先查清它是否覆盖了逐字段之外的场景
      ——例如一个**从未挂靠任何段**的会话。票面要回答这一条,**不许两套并存了事**
- [ ] `segment-card.ts` 也自己算了一份轮数,一并对齐到同一个来源

## 必须钉住的

- [ ] 写 `next_steps` 之后,`constraints` 的欠账**仍在**——独立断言,不要和「提醒出现了」合并
- [ ] 突变:把「只重置自己」改成「全部重置」,必须有测试变红
- [ ] D5 的裁决落地后,断言**只有一条**维护提醒通道在产出文本
