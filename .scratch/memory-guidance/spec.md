# 段维护提醒 —— 逐字段、分级、自带判据

**状态**:未实现。与手上的容器统一批次**无耦合**,可独立发。

**用户裁决**:[S15069/T1752](逐字段计时 + 说明何时该更新)、[S15069/T1753](间隔分级、一次只报一个、开 `memory-guidance` lane)。

---

## 问题

### 1. 提醒把判断转发给了一份不包含它的文档

工具描述里的原话:

> 20-turn reminder: check membership, Working State, whether to create or attach —
> **judgment lives in the Memory Rubric, not here.**

实测 rubric 的行动原则(6060 字符)里:**没有 `constraints`,没有「工作状态」,没有「维护」**。它只有两节——写 turn 笔记、什么时候去读。**段维护一个字都没有。**

于是提醒响了、agent 去 rubric 找、找不到,只能退回工具描述里的**字段清单**。而字段清单说的是「每个字段装什么」,不是「**什么东西值得被写下来,以及写到哪一级**」。

### 2. 后果是可测的

同一个会话里测到:真正改变行为的三条规则**全部来自注入的 `constraints`**(python 扫控制字节、worker 领地按文件划、`bun:sqlite` 的 `exec` 吞异常),而**逐轮笔记一条都没被读**。

同时:「绝不用 `git restore`」这条教训被写进了**五份 worker 简报**,一次都没进 `constraints`。它随会话消失。**没有任何引导告诉过我该往那儿写。**

### 3. 一个计时器不是一条判据

现行触发是「20 轮没有任何字段更新」。它:

- **无事可记时照样催** —— 20 轮杂谈之后它一样响;
- **刚立下一条重要规则时保持沉默** —— 只要碰巧刚写过别的字段;
- **不区分字段** —— `goal` 半年不变是对的,`next_steps` 20 轮不变是欠账,它一视同仁。

E60 当前的逐字段实况(取自 `write_gate_stamps`,实现时须重测):

| 字段 | 最后写入 | 距今 |
|---|---|---|
| next_steps | 08-27 00:09 | 0 小时 |
| constraints | 08-26 11:31 | 13 小时 |
| reference | 08-26 04:43 | 20 小时 |
| done | 08-24 01:50 | 70 小时 |
| decisions | 08-22 04:04 | 116 小时 |
| goal | 08-19 23:50 | 168 小时 |
| content / insight | **从未写过** | — |

## 解法

**逐字段计时,间隔分级,判据随提醒一起送到,一次只报一个。**

---

## 用户故事

1. 作为主 agent,我想知道**哪一个**字段该更新了,而不是「Working State 该看看了」,这样提醒指向一个动作而不是一次巡检。
2. 作为主 agent,我想在提醒里直接读到**什么情况该写这个字段**,这样我不必去另一份文档找一段并不存在的判据。
3. 作为主 agent,我想知道一条经验该进 `constraints` 还是 `decisions` 还是留在本轮的 `insight`,这样持久的规则不会被埋进逐轮笔记里等人搜。
4. 作为主 agent,我不想被 `goal` 每 20 轮催一次,这样提醒不会因为一直无理由地响而被我整体无视。
5. 作为主 agent,我想在多个字段同时到期时只收到**最该动的那一个**,这样提醒的说服力不被稀释。
6. 作为维护者,我想让计时读的是**已有的**逐字段写入戳,这样这个功能不引入新的状态。
7. 作为维护者,我想让一次真实的字段写入**重置那个字段自己的**计数,而不是全部字段的,这样写了 `next_steps` 不会把 `constraints` 的欠账一起抹掉。

## 实现决策

### D1 —— 逐字段计数,读既有的戳

`write_gate_stamps` 主键就是 `(entity_type, entity_id, field)`,已经逐字段记录 `written_at_epoch`。计数读它,**不加新列、不加新表**。

一次写入只重置**它自己那个字段**的计数。今天的全局 `sessions.last_remember_turn_id` 语义(任何 remember 写入都重置)与本决策冲突,由 D5 处理。

### D2 —— 三档间隔

| 档 | 字段 | 间隔 | 它记的是什么 |
|---|---|---|---|
| 高频 | `next_steps` `constraints` `decisions` | **20** | 活的状态,天天变 |
| 中频 | `done` `content` `insight` | **60** | 阶段性结论 |
| 低频 | `reference` `goal` | **120** | 长期不变的锚 |

**为什么不统一 20**(用户原议):按当前快照,统一 20 会让**六个字段同时催**,其中 `goal` 168 小时未变**是正确状态**、`reference` 只在出现新指针时才该动。一个长期无理由响的提醒不只自己被无视,**它会连带训练读者无视同一通道里的其他提醒**——那正是这批要修的东西。

数字是**判断,不是测量**。实现后按真实触发频率复核。

### D3 —— 判据随提醒送到,不转发

提醒**自带**分流判据,不再指向 rubric。触发 `constraints` 时:

```
constraints 已 20 轮未更新 —— 本轮有没有产生一条在这个项目里会再次成立的经验?
  会再次成立         → constraints
  只对当前任务成立    → decisions
  只对这一轮成立      → 留在该轮的 insight,不要上搬
```

三行,只在被触发的那个字段上出现。**这条分流判据是本批真正的产品**;计时只是让它出现的机制。

每个字段各有一句「什么情况该写」,写进票面。

### D4 —— 一次只报一个

多个字段同时到期时,按**高频 → 中频 → 低频**、同档内按超期轮数取一个。

理由与 D2 同源:注入有预算,而**六条提醒的说服力低于一条**。其余到期字段不提,下次轮到它。

### D5 —— 全局计数的去留

现行 `sessions.last_remember_turn_id` 是**会话级、全字段**的,`hooks/note-reminder.ts` 读它。逐字段计数落地后它有两条路:

- **保留为兜底**:一个段长期完全没被碰过时仍提醒一次;
- **退役**:逐字段计数完全覆盖它。

**倾向退役**,因为两套计数并存意味着两条提醒通道,而它们会在同一个注入槽里互相稀释。但这要看现有兜底是否覆盖了逐字段之外的场景(例如**从未挂靠过任何段**的会话)——实现时先查清,再裁。**票面必须回答这一条,不得两套并存了事。**

### D6 —— 不改字段本身

字段集合、语义、写入方式全部不动。本批只改**什么时候提醒、提醒说什么**。

## 测试决策

### 接缝

- **主接缝 —— 提醒的渲染函数**。计数与选取都是纯函数:给定「逐字段戳 + 当前轮次」,输出「提醒哪个字段,文本是什么」。在这一层测,不碰数据库。
- **第二接缝 —— 戳的读取**(`write_gate_stamps` 查询)。给定库状态,输出逐字段的轮次差。
- **不新开接缝**:`remember` 的写路径已有自己的测试,本批只是让它写的戳被另一处读。

### 必须钉住的

- **一次写入只重置自己那个字段**——写 `next_steps` 之后,`constraints` 的欠账仍在。这是 D1 的要害,也是最容易实现成「全部重置」的地方。
- **分级真的分级**:构造一个 `goal` 超 100 轮、`next_steps` 超 20 轮的状态,断言报的是 `next_steps`。若两档实现成同一个数,这条会红。
- **判据文本随字段变**:`constraints` 的提醒必须含分流三行,`goal` 的不含。断言的是**这一个字段的文本**,不是「提醒里包含某个词」。
- **一次只出一个**:六个字段同时到期,输出恰好一条。

### 验收纪律

沿用突变验证。突变必须**先断言落地**(打印 applied),并且要能**区分**——把两个档位的数字改成相同、把「只重置自己」改成「全部重置」,各自指出哪个测试变红。

**特别提醒**:「一次只出一个」这条如果 fixture 里恰好只有一个字段到期,任何突变都是空的。fixture 必须让**多个字段同时到期**。

## 不在范围内

1. **rubric 里补一节段维护。** 注入有 9500 字符上限,加一节要先腾预算,而且本批的判据放在**提醒里**比放在 rubric 里更近——提醒出现的时刻就是要做判断的时刻。rubric 该不该也讲一句,单独裁。
2. **字段语义、字段集合。** 见 D6。
3. **结算侧。** 结算不维护段字段,这条提醒只对主 agent。
4. **注入槽的整体预算重排。** 本批只往里放一条更短的提醒,不动别的块。
