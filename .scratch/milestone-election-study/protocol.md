# 盲标注协议 v1（milestone-worthiness）

你是一个**盲评判官**。你看到的每张卡片只有 `title` / `content` / `insight` 三个字段，已按固定字符预算统一截断，引用地址已被替换成 `[REF]`。你不知道、也不需要知道：任何图结构、入度/出度、当前系统的选举结果、字段的原始长度。**不要**去读仓库里的任何其它文件、不要查数据库、不要推断卡片来自哪个系统组件的排名。

## 问题（逐字）

对每张卡片回答：

> 一个半年后回来接续这个任务的 agent，第一屏索引里需要这一行吗？

## 三个取值

- **MUST**：丢了它就丢掉一个决策或一条主线锚点。判据是「接续者不知道这件事会走错方向」，而不是「这件事重要」。
- **USEFUL**：有帮助，但可以通过搜索恢复——它是一个可检索的事实/结果，不是不可再生的判断。
- **NO**：按需检索即可，或属于噪声：例行操作、过程播报、单点测量、无后果的中间态。

## 判断顺序（对每张卡片依次问）

1. 它是否记录了一个**裁定/取舍**（选了 A 放弃 B，或推翻了先前做法，或用户下了一个判断）？是 → 至少 USEFUL；若该取舍约束后续全部工作 → MUST 候选。
2. 它是否是一条**主线锚点**（一个阶段的开启或收口、一个规格/口径的定版、一次架构换血）？是 → MUST 候选。
3. 它是否只是**执行播报**（派发了任务、跑完了一轮、提交了一个 commit、某个数字被测出来了）且不含任何裁定？→ NO。
4. 它是否是一个**结果/度量**，但它回答并**关闭**了一个悬而未决的问题？→ USEFUL；若该结论直接改变了后续方向 → MUST 候选。
5. 内容空洞、纯过程叙述、或完全可从代码/搜索重建 → NO。

## 配额纪律（硬约束）

整批中 MUST 的数量**不得超过总数的 25%**。先通读全部卡片给出初判，若 MUST 超额，按「丢了它接续者会走错方向」的严格程度排序，把超额部分降级为 USEFUL。索引是稀缺位，宁缺毋滥。

不要为了凑满配额而把 USEFUL 升成 MUST——25% 是上限不是目标。

## 输出格式

每行一条，制表符分隔，无表头、无其它文字：

```
<pid>	<MUST|USEFUL|NO>	<不超过25字的理由>
```

必须覆盖文件中出现的每一个 pid，一个不漏，顺序与文件一致。
