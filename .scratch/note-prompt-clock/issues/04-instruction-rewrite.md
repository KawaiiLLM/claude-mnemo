# 04 — 纪律文本重写

**What to build:** SessionStart 注入块与 note 工具描述围绕三条原则 + 3′ 重写(spec D6):第一批次还欠账(写或 skip)、当前 turn 留给下一轮、告警或更正授权单开。删除 0.9.11 的 result-independence 启发式;修订语义收拢到 replace:true。保留清单:不从清单行编造、笔记调用批内靠后、英文、<private> 禁入、预算回执、字段契约(含 insight 独立可读)。两个表面(注入块 / 工具描述)措辞同步,不得出现只有一处声明的规则。

## Skip 判据(用户定案 S15069 T577/T579/T580)

判定维度只有一个:**turn 有没有实质内容 —— 未来的检索者在其中找不到任何独有的东西,答 skip;反之必须写。** 打断与否、是否重复发送、是否笔记簿记,都不是判定维度,只是无实质内容的常见长相(用户 T580:枚举子类属过拟合,「打不打断也不重要」)。判据是「索引要不要它」,不是「这轮花了多少力气」。

检查方法(用户 T581):**假设把这个 turn 从历史里删掉 —— 对项目的决策、进展、连贯性无实质影响,就 skip。**

示例(仅示意,非类别清单):纯确认/催促;被吃掉的重复发送;补笔记/审计台账的簿记回合(其产出落在被处理 turn 的地址上,簿记回合自身无实质内容)。

红线保留:内容已出上下文且无批次顺带恢复 → skip,不编造;顺带恢复了转可写。
硬线保留:用户的裁决、更正、否决,哪怕零工具调用,必须写;有结论、被拒方案或教训的 turn,无论多短,必须写。

操作纪律并入既有三条:skip 与 note 同资格同载具(第一条的「处理」= 写或 skip,批内靠后);decline 后补真笔记无需 replace;及时作答 —— 琐碎 turn 下一批就 skip 掉,别攒。
