# 读写契约:一个门、一个渲染器

**Status:** implemented(read-write-contract 票 01–09/11–15,2026-08-19)——门(三判+读授权+印章)、统一渲染器、结算直写、视图重设计(pageBudget/turn 双预算、里程碑字典序选择、段选择器、id 多选)均已落地;新 ADR-0008。turn-edge-mechanism spec 留给「视图 spec」的消费侧验收缺口(里程碑准入与计分渲染)由此收口,其自身的 caveat 措辞未回改,读者遇到时以本行为准。

## Problem Statement

三个问题坐在同一条接缝上:

1. **写安全没有通则**。跨会话写 turn、写他 session、写段,今天各有零星防护(crossSession 确认旗、roster 先读后写、结算的可评窗+yield 栅栏),但没有统一规则。两个并发 session 挂靠同一段可以互相整字段覆盖,丢更新无任何栅栏;结算能整覆盖它只见过截断前缀的 session 叙事(2026-08-19 peer 审查 finding ②)。
2. **结算的 staged-commit 是专用机制**。它的三条栅栏——可评窗、yield、claim CAS——都是写安全通则的点状特例;通则落地后它是第二套并存机制。其原子性对「检查性质」的结算也是过度保证:纠错是不动点操作,每笔已落写各自完整合法,崩溃留下的是「部分结算的窗口」(窗口的常态),重试即收敛,不需要回退,也不需要 undo 日志([S15069/T952] 两项撤回)。
3. **视图重设计已裁决未成文**。四级升级梯、折叠/展开二态等十一个实测问题的解法已在 [S15069/T918]–[T921]、[T930](实证排序)、[T874]/[T876](里程碑准入与显示权威)裁定;其统一渲染器恰是读授权的天然记录点。读写两半共用这一个铰链,是两个 spec 合一的结构原因。

## Solution

一份**读写契约**:所有读面经统一渲染器出货并顺手记录读授权(Read grant);所有受管写面过同一个门(授权/例外/新鲜性三判);结算改逐笔直写过门,staging 不启用;recall/timeline 按已裁决的两形态重建,超 pageBudget 分页而非截断。

## User Stories

1. 作为主 agent,我想 recall 过一个段后直接写它的字段,以便读写衔接无额外仪式。
2. 作为主 agent,写从未读过的实体时,我想收到「先 recall X」的报错,以便知道缺的是读。
3. 作为主 agent,写已被他人改过的字段时,我想收到「X 已被 S123 于某时改过,重新 recall」的报错,以便基于最新值重写,并与「未读过」区分。
4. 作为主 agent,写自己刚写过的字段时,我想永远放行(写即是读),以便本会话连续工作不被门打断。
5. 作为主 agent,首次写从未被写过的字段时,我想放行,以便创建类操作不必先读空值。
6. 作为主 agent,误把他 session 地址当自己的写时,我想被 crossSession 旗拦住,以便授权挡不住的误寻址仍有一道意图闸。
7. 作为并发的第二个会话,与他会话挂靠同一段时,我想双方的字段写互不静默覆盖,以便丢更新不再发生。
8. 作为结算 agent,我想逐笔直写、每笔立即校验并落库,以便冲突在写时暴露、当场重读重判,而不是攒到 commit 才发现。
9. 作为结算 agent,我想在 prompt 里看到 session 叙事全文,以便整覆盖不丢我没见过的尾部。
10. 作为结算 agent,我想 agent 晚到的笔记使我对应字段的授权失效,以便 yield 语义成为新鲜性通则的自然推论而非专用机制。
11. 作为结算 agent,run 途中死掉时,我想已落的每笔写保持有效、窗口在下次事件触发时重试收敛,以便无回退、无脏区。
12. 作为结算 agent,我想 commit 只做 claim 校验+计数回执+终态标记,以便空手窗口与满载窗口同样干净完成。
13. 作为运维者,我想网络/连接失败不耗重试次数、也无主动重旋,由下个结算触发事件(如 Stop hook)自然再试,以便重试永远事件驱动。
14. 作为运维者,我想确定性失败最多重试一次,之后弃窗留欠账、游标推进,以便终态不阻断后续窗口。
15. 作为使用 recall 的 agent,我想用 filter 选字段、pageBudget+turn 两个预算控制体量,以便一个工具从浏览覆盖到细读。
16. 作为浏览者,我想按全局时序读、session 交替只在首现带 title,以便叙事连贯不重复。
17. 作为搜索者,我想命中按分数排、匹配词加粗并带邻域文本,以便先读最相关证据。
18. 作为读者,我想超 pageBudget 的内容分页而非截断,以便预算控制节奏而不吞内容。
19. 作为读者,我想 rewind 的 turn 渲染时带标记、其 transcript 指针不被信任,以便不把撤回分支当有效结论。
20. 作为读者,我想 obs 恒截断,以便重型实现 turn 不淹没页面。
21. 作为冷启动的会话,我想 SessionStart 注入里程碑视图作为全局关键 turn 索引,以便开场即有导航。
22. 作为里程碑读者,我想准入按集合原则(只读选中集即最大化理解任务决策)、选择按字典序信号(encodes 降序、refines 超额降序、时近),以便重要性来自边推导而非赋值。
23. 作为引用者,我想序数 T 只用于选择、`S<n>/T<m>` 是唯一引用形式,以便引用不随后续归属漂移。

## Implementation Decisions

### 门(写面)

- **受管面**:跨会话 turn 写、session 字段写(含结算的叙事)、全部段写、结算四字段纠错。边写入不新增门规则——既有引用纪律与 pre-run 资格快照原样保留。
- **三判次序**(逐字段):(1) 本会话读过该实体(注入或 recall/timeline 渲染过,实体级授权=全字段)且该字段未被其他写者后写 → 放行;(2) 未读:该字段上次写者==本会话 → 放行;(3) 未读:该字段从未被写过 → 放行;(4) 否则拒绝。报文两分:「未读过 → 先 recall <地址>」/「已失效 → <字段> 已被 <写者> 改过,重新 recall」。**门判定、写入与印章更新在同一事务内完成**(检查-写入原子)——row 级 updated_at + 整行 UPDATE 不构成字段门;不存在「双方都判过门、后写静默覆盖先写」的窗口。显式 null 清空是一次写(盖印章),清空后的字段是「被写过」而非「从未写过」。
- **写者身份**:主 agent 借 crossSession 闸的同源身份链(caller-session 解析);**结算写者身份=claim generation(每次认领一个新身份)**——失租的旧认领者与新认领者互为「其他写者」,新鲜性门天然互斥两者,claim 栅栏不再需要独立的逐写检查。agent 与结算之间同理双向作废。resume 导致会话 id 变化,接受。
- **读集**:一张表(写者、实体类、实体 id、read_at),**统一渲染器渲染即记录**——注入与工具渲染同一记录点。无 TTL,只被写作废;session 终结时清理其读集,janitor 兜底。
- **新鲜性印章**:一张字段印章表(实体类、实体 id、字段、最新写者、**单调序列号**)。用序列号而非整数秒比较——现 yield 栅栏的 `>=` 秒级比较会把同秒早写误判为晚到,新印章不继承此歧义。**字段映射**:agent 的笔记写入同时为其 turn 的 note 派生字段(type/tags)盖印章(写者=agent 会话)——「yield 被字段级失效包摄」由此成立,否则笔记写的是 note 实体、盖不到 turn 字段。rewind 撤销印章 v1 不做(需印章历史日志,已知缺口:被回退分支的写仍会作废他人授权一次)。
- **crossSession 旗保留**:门防「没读过就写」,旗防「读过但写错对象」,正交。
- **主 agent 写本会话 turn 无专门豁免**:首笔=从未写过,改笔=写者是自己,经三判天然放行。
- **受管写者含 hook**:Stop handler 的会话收尾写改**窄更新**(只写其自有字段,如 completedAtEpoch),不回写开场读取的整行——「开场读、收尾整行 upsert」会静默覆盖结算中途写入的叙事,这个 TOCTOU 以窄更新根治而非过门。

### 结算(直写改造)

- **触发与窗口**([S15069/T963] 裁决,替换现行 20 窗+compact 即触发):唯一自动触发=turn-stop 规划;门槛 **25 个连续已定型 turn**,单次窗口上限 **50**(范围 [25,50]:攒 60 → 切 50 留 10 待续)。**compact 与 sessionend 不再立即触发**——结算读库不读活上下文,压缩销毁的语境与其无关;检查性质的工作不需要即时性。已知后果并接受:会话终止时不足 25 的尾巴保持未结算(欠的只是复核,首写俱在);残余通道照旧只搭车认领已成窗的账上作业。
- **前序注入**:数量=**与本窗口 turn 数相同**(25 窗配 25、50 窗配 50);**对 subagent 前序与目标无区别**——统一渲染、统一可纠(渲染即授权,与门同构);窗口边界只是作业记账(游标推进与终态归属),不再是 prompt 侧的职责分界。
- **手动补录**(/settle backfill):**无前序注入**,单次上限 **100 turn**。
- remember/note **逐笔直写**:每笔即时过门+落库,回执即收。**接线改造在本 spec 范围内**——handler 从 stage* 改直写、commit 与 Stop hook 按下述重实现;仅 staging 死代码的物理删除留给后续减法票(与「不启用」不矛盾:发版行为即直写)。pre-run 资格快照保留(自授权栅栏与写落时机无关);yield 栅栏由字段级失效包摄(依赖上节的 note→turn 字段印章映射),不再是专用检查。
- **归属纠错写事务内重验**:该段当前仍挂靠本会话才放行——roster 快照仅作提示,写时以库上现状为准(渲染后被 detach/close 的段不可再收成员)。
- **propose 携幂等键**:**session+规范化 addresses** 唯一约束(2026-08-19 修订:job 键无法跨重认领去重——重试=新 job id;title 不入键)——已落库窗口的重试自然去重,回执报「已存在」;撞键时 **title 刷新**为最新提案(后一次 run 后见之明更全);「无回退+重试收敛」对 INSERT 型写由此成立。
- **commit 重定位**:claim 有效性检查+本 run 各类写入计数回执+作业终态标记。不判职责覆盖(空手窗口本就合法)。
- **Stop hook 重实现**:直写模式的完整性探针=「job 已认领未终态」(staged 计数已无意义);hook 持 jobId 与 claim generation,agent 未调 commit 即停 → 走确定性失败记账路径(计入那次重试);「没有 staged 写入、commit 是唯一 writer」的旧文案随语义一并改写;拦截上限行为保留。
- **重试**:确定性失败上限 1 次;网络/连接错误不耗次数、**无主动重试**——事件驱动,下个结算触发点再试(借提取管线 0.6.6 的重试哲学)。1+1 后弃窗:留欠账记录(窗口区间+放弃原因,供手动 /settle 补),游标推进,终态不阻断后续窗口。
- **作业状态机相应扩展**(现状不兼容,须迁移):失败类别列区分暂时性(网络/连接/SQLITE_BUSY——不计 attempts、不 backoff、留队列等事件)与确定性(计 attempts,上限 1);现行「claim 即 attempts+1、失败一律 backoff、上限 3」语义废止;新增 abandoned 终态;既有 failed 行按确定性语义迁移。
- **session 摘要注入**:走统一渲染器,结算消费方传**大 turn 预算**(唯一写者看全文档);主 agent SessionStart 用默认预算。旧「溢出→截断+recall 指针」的会话状态渲染路径随统一渲染器退役。
- ADR-0007 的 staged-apply 半边由本 spec 取代,落地时标 superseded;单工具面半边不动。

### 视图(读面)

- **一工具两形态**:无 query=浏览(全局时序,session 交替仅首现带 title);有 query=搜索(分数序,匹配词加粗+邻域,词边界截断均摊)。折叠/展开二态废除,字段选择走 `filter`,每字段的 schema 描述各自成段并完善报错。
- **预算**:pageBudget(页级,溢出→**分页**,绝不截断整块)+ turn(item 级,字段内容的唯一一把刀,词边界截断)。**只有这两个 token 预算**——旧 `truncate` 字符参数(默认 200/上限 2000)及其字符上限机制整体退役([S15069/T972] 裁决);obs 恒截断,由 turn 预算驱动。
- **选择器**:序数 T(段内时序位次)只作选择;`S<n>/T<m>` 唯一引用形式。报错回显语法。
- **timeline**:turn 视图与里程碑视图仅差 pageSize 驱动的重要性选择;`timeline(id="E31/T1...")` 与 `timeline(id="E31")` 同构。段选择器为新增能力(现 timeline 只解析 S 地址):数据范围=该段成员 turn 的跨 session 时序,输出一律以 `S<n>/T<m>` 回指,分页语义与会话视图同构。SessionStart 注入里程碑视图。
- **里程碑**:准入=集合原则([S15069/T874]:选中集单独可读即最大化理解任务决策);选择=字典序信号(**第 0 键:overridden 除名**;encodes 降序、refines 超额入度降序——**decision 桶先于 delivery 桶**;时近),填满 pageSize;选择是唯一显示权威,箭头标记是纯地址索引([T876]);无边图安全退化(平铺时序)。信号层已落地(edge-signals),本 spec 只消费。
- **rewind**:渲染带标记;其 transcript 指针视为失效坐标,replay 不信任。
- **统一渲染器**:全部读面(recall/timeline/注入)的唯一出货点,授权记录是其副作用——读写契约的铰链。
- **roster 重建**([S15069/T978] 裁决):roster 块=统一渲染器出货的段列表,与 rubric **分块**(rubric 独占自己的块);活跃时近序;item 预算 100 tok、page 预算 2000 tok,分页默认展示第一页;字段仅 **title、tags**。随之退役:topic 分组表头、type facet 字形、40 段上限(分页取代)、标题字符截断、与 rubric 的合租及其省略标记逻辑。
- **选择器多选**([S15069/T979] 裁决):`id` 接受逗号分隔列表(如 `id="E31, E32"`),各项按既有语法解析、按序渲染、共享页预算;渲染即授权对列表全部项生效;混合类别或任一项非法时整调用拒绝并回显语法。

### 节奏与建段指导([S15069/T978] 增补)

- **全会话统一提醒**,不分有无挂靠:每 20 turn 一次 remember 检查提醒(UserPromptSubmit 通道——持久化进 user message,缓存安全;计数自上次 remember 调用起);note 积压 >5 时提醒(既有 backlog-relief 块,阈值确认)。段卡片头的 20 轮维护 nudge 后缀退役——其职能并入统一提醒。
- **rubric v3 增「建段」节**(判断层;时机归 remember 工具描述):琐碎、短时闲聊等组不成可命名工作流的 turn 无须建段,无归属合法;需要建段先查 roster 有无合适已有段,挂靠优先于新建;无合适段才新建,以任务实际形状命名。
- **remember 工具描述**补一行调用时机(20 轮提醒到达时检查:归属、Working State、是否该建段/挂靠),工具描述=时机+作用,判断原则指向 rubric。

### 迁移

- 发版即默认直写+门;staging 代码物理拆除是后续纯减法票,不在本 spec。

## Testing Decisions

- 好测试只测外部行为:报错文本形态、落库结果、渲染字节;不测内部结构。
- **最高接缝=MCP 工具面**:门的三判与两类报错、旗、「recall 后可写」「他人写后失效」全部经 note/remember 端到端;先例 tests/mcp/note.test.ts 的拒绝-教学断言。
- **结算派发面**:直写落库、commit 重定位、重试记账与弃窗欠账;先例 note-settlement-call/staging 测试(staging 断言改写为直写断言)。
- **渲染器面**:两形态、分页、turn 预算、授权记录副作用;先例 timeline/recall 的格式测试。
- **hook 面**:SessionStart 注入即记录读集;先例 session-composition 测试。

## Out of Scope

- rewind 的印章撤销(需历史日志,记为已知缺口)。
- 独立的 generation 逐写校验机制(不再需要:结算 per-run 写者身份使新鲜性门天然互斥新旧认领者)。
- staging 代码的物理拆除(后续减法票)。
- tag 计分、视图在已裁决集之外的新功能、发版本身。
