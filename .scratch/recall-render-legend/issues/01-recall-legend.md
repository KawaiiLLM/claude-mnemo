# 01 — recall 渲染的导航样板收敛

**What to build:** 一次 recall 展开渲染里，「被截断的内容可以读全文」这句话只说一遍。字段被截断时只留既有的省略标记，导航指令改为整个响应末尾的一行图例；本次响应没有任何截断时，图例不出现。同一票内解决观察记录标签行与 `tool:` 行的同义反复——标签本身已经就是工具名时不再单出 `tool:` 行，判据是两者是否相等而非 turn 属于哪个纪元（旧纪元有提取器标题，两者必然不等，行为不变）。

对读者的净效果（S15069/T485 实测，改动前后各渲染一次）：turn 展开 4,298 → 3,572 B（**16.9%**），observation 列表 `S…/T…/O*` 23,763 → 17,417 B（**26.7%**）。下钻能力一点没少——省略标记仍指出哪里被截，`[O…]` / `[S…/T…]` 仍是地址，图例把两者接起来。

**内含预重构（先做）：** 渲染需要知道「本次响应是否发生过截断」。截断目前是纯函数，答案随返回值丢弃，因此要引入一个渲染作用域的截断信号。**不得改为扫描最终字符串里有没有省略标记**——用户内容本身可能含省略号，那是把正确性押在数据上。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 一次含多个被截断字段的展开渲染里，导航句只出现一次
- [ ] 本次渲染没有任何截断时，图例不出现
- [ ] 被截断的字段仍带省略标记，截断预算（`truncate` 默认值与上限）不变
- [ ] 图例措辞不含自造词，直接给命令名与 id 形态；一行讲完，不拆成多条
- [ ] 新纪元观察记录不再出现与标签重复的 `tool:` 行
- [ ] 旧纪元观察记录**依然完全不带机械字段**（工具名也不带），因此没有 `tool:` 行——本条初稿写反了，见 spec D3 的更正；判据是标签是否等于工具名，不含纪元分支，只是旧纪元一侧永不触发
- [ ] 截断信号不依赖对渲染结果的字符串扫描
- [ ] 断言写在现有接缝上（recall 渲染结果字符串），不新增可测点
- [ ] 全量测试绿
