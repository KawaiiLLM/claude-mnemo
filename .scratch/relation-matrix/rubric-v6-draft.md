# Rubric v6 §关系 draft (review copy — the splice source)

## 关系(turn→turn;从引用方记向被引方)

- 正文与边脱钩:content 不要求任何引用格式,提到一个 turn 不必标注;
  边由关系参数独立声明。
- 选词只看相位,两条读法:
  同相位(源靶同属 取证/决策/落地)→ 按担保强度选:
  · override — 被引主要结论错,本节点可替代它;被 override 者分数归零
  · refines — 被引主要结论对,在其上改进/补充/拓展,不可替代;被 refines 者
    加分。改进链是分叉:每条链 = 从起点分出的一个方向,指向你真正基于的
    节点,不同方向不按时间顺序串连
  · depends-on — 仅担保逻辑依赖:建立在被引方完成的基础上,不问工作流、
    不担正确性;派工→验收→提交等工序链合法
  跨相位 → 词由源相位唯一决定:
  · 取证源 → evidence-for / evidence-against:裁断——我检验了那条主张
  · 决策源 → grounded-on:立足——它假则我塌
  · 落地源 → encodes:承载——被点名者加分,故只点名本次落地的核心决策
    与关键验证:值得展示的最小集
- 同流约束只压 override/refines:两端须同一工作流——工作流 = 可分离、
  可命名的子任务链路;判不清同流,降级用 depends-on。
- 每个完结 turn 过三步;有多个候选直接前驱时,对每个分别过问:
  1. 有直接前驱吗?前驱 = 直接引起这一轮的节点;跳级指向弧起点是错标。
     没有 → 孤儿仅两类合法:未曾设想的子任务起点 / 无决策闲杂;不为消灭孤儿编边。
  2. 有 → 按两条读法选词;无词可选 → 不记。
     同对 turn 可并存多条关系,但每条必须表达不能由其余关系推出的独立事实:
     逐条移除检验——refines 成立时 depends-on 可由它推出,不另写。
  3. 被拒?合法性由校验器机器检查,拒绝信息说明缺哪一半 → 补足最小缺失的 type,或改判关系。
- override/encodes 是软断言:拿不准 override,用 refines。
- 发布仪式:发布 turn 收拢它交付的落地(depends-on)与它固化的裁决(encodes);
  存在上一次发布时引用它,首个发布是发布链的合法根。
- 撤边:发现边为伪时撤除,按需改写——撤除与改判同为判断行为,不为整洁而撤。
