# 状态／里程碑分层注入 + turn 五级显著度制

**Status:** ready-for-agent

## Problem Statement

SessionStart 注入的会话层把两种时效性完全不同的信息挤在同一次 7 字段全量重写里：「当前状态」（current／next，续接工作最需要）与「历史台账」（decision／done 的三个月累积）。渲染顺序是 content → decision → done → current → next，截断方向与价值方向相反——2000 预算实际保住的是最旧的发布史，砍掉的恰恰是 current／next 与最新决策。实测（S1730，907 turns）：摘要字段未截断 4,824 token，里程碑时间线 4,520 token 在注入路径上输出为零；decision 12 条、done 12 条双双超出 ≤6 的票面上限且互相重复记账。

同时，里程碑选择的基础分由 type 查表得出，无法区分同 type 下的重要性差异（同为 feature，「ticket 验证提交」与「0.5.0 发布部署」差一个量级），会话内的「大局观」既没有可靠的选材信号，也没有独立的注入通道。

## Solution

会话记忆拆为**状态层**与**里程碑层**两条独立注入，各 2000 token：

- **状态层**：只记「对下一步工作最有用的部分」，实时更新与剪枝，写入时硬校验超限失败、agent 自行重裁；
- **里程碑层**：提供会话内历史大局（做过什么、决策过什么的模糊印象），选材基础分改由提取 agent 逐 turn 打的**五级显著度等级**提供，corrector 晋升与互引入度保留为结构修正层。

注入矩阵按 source 分流：startup/clear 注入用户画像 + 近期会话/日记索引（历史大局无检索先验，必须常驻；但新会话没有会话内状态可注）；resume/compact 注入全部四条。经历文档（experience.md）退出注入，由近期会话 + 日记索引替代（三者粒度重叠，后两者是 mnemo 独有信息）。

## User Stories

1. 作为续接工作的 agent，我要在 resume/compact 后第一屏看到 current 与 next，而不是三个月前的发布史，以便立即知道该做什么。
2. 作为续接工作的 agent，我要一份不随会话长度膨胀的会话内大局（全部 4 级旗手 + 近期 3 级 + 择优 2 级），以便不重新提出已被否决的方案。
3. 作为无领域先验的用户（如非计算机专业者指挥 coding agent），我需要大局意识被常驻注入而非按需检索，因为不知道自己缺什么就无从检索。
4. 作为提取 agent，我要在每个 turn 打一个 0–4 的显著度等级并可随时修正先前 turn 的等级，以便里程碑选材反映语义判断而非 type 查表。
5. 作为提取 agent，当我亲眼看到某高等级 turn 被后续证伪／回滚时，我要将其降级（误导 turn），纠正 turn 获得相应等级；反转记录由 corrector 以 ↳ 伤亡形式保留。
6. 作为提取 agent，当一段弧线出现更具代表性的节点时，我要把旧 4 级降为 3 级，保证每段弧线至多一名旗手。
7. 作为提取 agent，我要每 10 turn 收到一次近 100 turn 的等级分布统计与参考基线，以便自查漂移；基线仅供校准，不强制遵守——分布因会话性质而异，不得为凑分布改判。
8. 作为 summary agent，当状态层渲染态超过 2000 token 时，我要收到写入失败与各字段 token 明细，以便自行剪枝重写。
9. 作为 summary agent，done 字段我只记录近期、对 next 工作可能有用的细粒度完成事项，历史成果交给里程碑层沉淀。
10. 作为读注入的 agent，我不要看到同一溢出目标的指针行重复多次，整份文档收敛为末尾一条指针，仅当某节溢出目标与文档级不同时保留节级指针。
11. 作为读注入的 agent，我要在状态层看到 `[T<n>]` 引用坐标但不要标题展开（展开使渲染体积膨胀 2–2.5 倍），标题展开是里程碑层的职能。
12. 作为 startup 的新会话，我要注入用户画像与近期会话/日记索引各 2000 token，且 sessions hook 的副作用（session 建行、markSessionRunStart、diary reconcile）照常执行。
13. 作为旧数据的持有者，等级为 NULL 的历史 turn 要回退到 type 查表基础分，无需回填。
14. 作为运维者，我要 dream agent 继续维护 experience.md（供按需读取与 dream 自身上下文），仅注入侧移除。

## Implementation Decisions

### 五级显著度（0–4）

新增 turn 层等级列，由提取 agent 在 turn 摘要写入时赋值，并允许对先前 turn 修正。等级语义与判据（实证取自 S1730）：

| 等级 | 语义 | 判据 | 参考基线 |
|---|---|---|---|
| 4 顶层 | 弧线旗手：一个 turn 浓缩一整段对话弧的精华 | 「能否独自代表其后数十个 turn 的存在理由」；每弧线至多一个 | <2%，全会话个位数 |
| 3 里程碑 | 改变后续工作前提：发布验证、锁向决策、路线反转、重大根因 | 「之后的工作是否都建立在它之上」 | ≈8% |
| 2 显著 | 弧线节点：票据完成并验证、实测纠错、有据否决、真实缺口 | 「回顾本会话时值得单列一条」 | ≈25% |
| 1 常规 | 过程性进展：中间验证、调度杂务、答疑梳理 | 「一周后无人引用」 | ≈45% |
| 0 噪音 | compact／命令／空壳／未续中断 | 无叙事价值 | ≈20% |

提示词实例（来自 S1730，供 prompt 撰写）：4 级如「锁定事件驱动 worker 生命周期」；3 级如 T925（0.5.0 发布）、T909（设计收敛为 5 票）、T908（撤回反对认可关停）、T850（根因：watchdog 杀死重试循环）；2 级如 T917–T922（各票验证提交）、T896（成本 $6.38→$1.43 修正）、T928（中断 turn 孤儿缺口）；1 级如 T861–T864（例行确认部署）、T942（答疑解释）；0 级如 T941（/compact）。

修正职能两条：(a) 误导降级——仅在亲眼看到证伪／回滚证据时，把受害 turn 降级、纠正 turn 得相应等级，不得凭猜测改史（实证例：T894「dream 成本 $6.38」被 T896 证伪后应从 2 降为 1；反转记录由 corrector 以 ↳ 伤亡保留，不因降级丢失）；(b) 4 级唯一性——同弧线出现更佳代表时旧 4 降 3；被后续顶层决策推翻的 4 级同样走 (a) 通道。

漂移反馈：每 10 turn 在提取 agent 提示词中插入一次近 100 turn 等级分布统计 + 参考基线（间隔 10 是为保住提示词前缀缓存），措辞为校准参考、非强制。

### 计分融合

等级仅替换里程碑加权计分中的**基础分**（现由 type 查表），corrector 晋升与互引入度作为结构修正层原样保留——等级管「turn 本身多重要」，结构层管「后续历史如何改写它」。NULL 等级回退 type 查表。加权体系动了 0.2.38 的校准，需按当时的验证方法在私有 dump 上重跑确认选择质量不回退。

### 状态层（session summary）

- 字段收缩：content（一句弧线概述）、current、next、仍然生效的 decision、done（仅近期、对 next 可能有用的细粒度事项）、reference；历史成果与已完结决策不再保留，沉淀交给里程碑层（timeline 计分与摘要解耦，剪枝不产生双删）。
- 写入硬校验：按**渲染后的注入形态**计量（estimateDiaryTokens），>2000 则写入失败并返回各字段 token 明细，summary agent 自行剪枝重写；机制复用 commitNight 硬上限 + check_budget 的先例。
- 状态层注入渲染保留 `[T<n>]` 坐标但不做标题展开。
- 渲染防线：硬校验只约束新写入，存量未经校验的会话续接时仍会超限，状态层注入保留渲染端 2000 预算兜底；渲染字段序调整为 content → current → next → decision → done → reference，使兜底截断先砍历史而非砍状态。

### 里程碑层（第四条注入）

- 内容：现有 milestone timeline 视图，基础分改为等级驱动；渲染预算 2000。
- 降级顺序：shape signals 块 → ↳ 伤亡行 → prompt 截断 80→50 → 均匀减少保留 turn 数（不砍最旧的天，避免「大局」退化为「近期细节」）。
- 提示 agent 细节自查：溢出处给 `timeline()` 指针。

### 渲染端

- 指针行去重：整份文档末尾一条指针；仅当节级溢出目标与文档级不同（如 persona 指文件路径、sessions 指 recall）时保留节级指针。

### 注入矩阵

| source | 状态层 | 里程碑 | 画像 | 近期会话+日记索引 |
|---|---|---|---|---|
| startup / clear | – | – | ✓ | ✓ |
| resume / compact | ✓ | ✓ | ✓ | ✓ |

- matcher 保持全量（startup|resume|clear|compact），按 source 的分流在 handler 内做——「不注入」不等于「不运行」，sessions hook 的副作用在所有 source 下照常执行。
- 第三条 hook 内容从 experience + 日记索引改为 Recent Sessions + 日记索引；experience.md 仍由 dream agent 维护，仅退出注入。
- Recent Sessions 的溢出指针指向裸 `recall()`（修复现状指向 `recall(id="S<n>")` 的错位）。

## Testing Decisions

- 只测外部行为：给定构造的 turn 集与等级，断言里程碑选择结果与渲染预算；给定超限摘要写入，断言失败返回与明细；给定四种 source，断言各 hook 输出的有无与内容隔离、副作用恰好一次。
- 计分融合需在私有 dump 上重跑既有验证方法（0.2.38 时的对照评估），确认等级驱动基础分后 GOLD 召回不回退。
- 先例：hooks 上下文注入测试（三路拆分回归）、worker 摘要工具测试、timeline 加权选择测试、persona 渲染预算测试。

## Out of Scope

- dream agent 的行为改动（experience.md 的维护、日记生成均不变）。
- 历史 turn 的等级回填。
- 队列卫生（陈旧 pending 项清理）与本批四个未发布提交的发布流程。
- 跨会话的全局里程碑层（本设计的里程碑明确为会话内大局）。

## 否决的备选方案

- **粘性引用台账**（摘要重写时把 decision/done 引用过的 turn id 记入只增台账、作为计分信号）：败于「进 session 摘要的 turn 不一定需要进里程碑」——沉淀与否是语义判断，被动记账无法表达，改由 agent 等级承担。
- **硬钉 always-keep**（被剪 decision 的来源 turn 永久保留）：败于钉子只增不减、终将撑爆 2000 预算，与「保证」自相矛盾；「较高竞争分数 + 允许淡出」才与「模糊印象」的语义一致。
- **里程碑按需拉取（不注入）**：败于大局无检索先验——不知道自己缺什么就无从检索。
- **跨会话全局里程碑层**：本设计的里程碑明确为会话内大局；跨会话叙事由近期会话 + 日记索引承担。
- **等级替换整个加权计分**：败于 corrector 晋升与互引入度是单 turn 视角看不见的结构信号（反转只在事后可见），保留为结构修正层。

## Further Notes

- 等级新增为 turn 表新列而非新 status，规避「新增 status 破坏 `!= 'active'` 假设」的既往教训；新列上线后需 grep 现有 turn 查询确认无隐式假设。
- 提取 agent 的等级修正走既有 turn 修正通道，摘要工具 schema 增加 regrade 类字段。
- 每 10 turn 的分布统计是一条 SQL（近 100 turn group by 等级），token 成本一行。
