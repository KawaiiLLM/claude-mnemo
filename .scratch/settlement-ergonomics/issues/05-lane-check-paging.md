# 05 — lane_check 分页与聚合

**What to build:** `lane_check` 的输出落在一个人(和一个 agent)读得完的范围内。
今天它零参数、一次性全量,实测 128,100 字符,直接撞爆工具结果上限——那一轮等于没有校验器。

对应 spec:D3 的 1、2、4(第 3 项「只报可修的」是 06 票,需要 04)。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 参数 `page`(1 起)与 `pageBudget`(与 recall 同名同义);溢出翻页,永不截断块
- [ ] 每页末尾带续读提示:还有几页、下一页怎么要
- [ ] 同类警告折成一行加计数与前若干实例地址
- [ ] **两条独立断言,不得合并**:
      (a) 分页真的活着——构造一个聚合之后**仍然超过一页**的 fixture,断言第 1 页、
          续读元数据、第 2 页的覆盖;
      (b) 硬上界——默认调用字节数小于工具结果上限
- [ ] fixture 必须是**提交进仓库的确定性大 fixture**,覆盖每一个无界报表家族各一份。
      不得读生产库(套件有 HOME 沙箱),也不得用三条泳道的玩具形状
- [ ] 突变:把预算调成无穷,(a) 必须变红
