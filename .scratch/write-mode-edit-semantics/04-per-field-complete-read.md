# 04 — 渲染记录授权时,一并记下哪些字段完整交付了(prefactor)

**What to build:** 一次渲染在记录读授权的同时,记下**本次完整交付了哪些字
段**。票 06 的 `write` 判定要靠它回答「这个写者读全过这个字段没有」。

本票只记录,不判定。

**Ruling base:** spec D8。这是 spec 自己的设计决定,不在用户裁决内——理由是它
避免新增一条「全文读」的读面参数,让完整性成为普通渲染的副产品。

**Blocked by:** none。

**Status:** ready-for-agent

## Pinned decisions

- **复用渲染器已有的逐字段截断信号**,不新增读面参数、不新增一条专用的全文读
  路径。字段短到装得下预算时天然完整;长字段由写者提高预算重读来换取。
- **粒度是逐字段,不是实体级。** ADR-0008 的授权本身是实体级(一次出现授权全部
  字段),但完整性必须逐字段:`write` 是逐字段操作,实体级完整性会让一个长字段
  的截断连坐同实体的短字段。
- 记录与授权同一次写入、同一个事务,沿用授权已有的「渲染开始时快照序列号」纪律
  ——完整性属于那一次渲染看到的状态,不是记录时刻的状态。
- **只读句柄下不得因此新增任何写入**,与票 01 同一条纪律。票 01 移除的是段块槽
  的写者身份,本票不得从别处把写再引回只读路径。
- 不改判定逻辑:门在票 06。本票交付的是数据与写入它的接缝。

## Acceptance criteria

- [ ] 一次未被截断的字段渲染后,该字段被记为完整。
- [ ] 一次被截断的字段渲染后,该字段**不**被记为完整。
- [ ] 同一实体上一长一短两个字段同时渲染:长字段截断不影响短字段的完整记录。
- [ ] 同一字段先截断后完整地读两次,以后一次为准(不因先前的截断而永久失格)。
- [ ] 只读句柄下渲染不产生任何写入(与票 01 的断言并存而不冲突)。
- [ ] typecheck 干净;全套绿,只余既定的陈旧包守卫红。
