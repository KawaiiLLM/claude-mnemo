# 06 — 门:两种模式同受失效,`write` 额外要求读全过

**What to build:** 覆盖一个已有内容的字段前,写者必须读全过它;改其中一段则不
必。两种模式都受「他人在我读后动过它」的失效判定。被拒时,报文能区分三种成因并
各自给出补救动作。

**Ruling base:** spec D2、D5、D6([S15069/T1056] 的未截断裁决;
[S15069/T1058] 否掉初稿 D6 的松弛)。

**Blocked by:** 04(完整性记录)、05(模式词汇)。

**Status:** blocked

## Pinned decisions

- **初稿的「`edit` 跳过读授权」作废。** 裁决是「看见」与「内容一致」两个前提并
  存,不是前者可由后者蕴含——写者能从过期的注入里猜出一个恰好唯一命中的
  `oldString`,匹配因此不能替代授权。两种模式一律走 ADR-0008 的三判次序。
- **初稿的「容忍无关并发变动」作废。** Claude Code 的 Edit 工具在文件自读后被
  外部修改时会拒绝并要求重读;初稿那条松弛是自造的,且正是加行乱序的根源。字段
  在本写者读后被他人写过 → 两种模式一律拒。
- `write` 在三判之上叠加:覆盖**已有内容**时,本次授权必须来自一次未被截断的该
  字段渲染(票 04 的记录)。字段为空或从未被写过时不要求——那是新建路径,没有
  可丢的旧内容。
- 拒绝报文三分,措辞可区分:未授权 / 失效(指名另一位写者)/ 读不完整(**必须
  指名是哪个字段、补救动作是提高预算重读**,否则写者无从下手)。
- `edit` 成功后照常盖章,别的写者据此判失效。
- 判定与写入仍在同一事务内,ADR-0008 的「检查-写入原子」不变。

## OPEN — 必须先裁决,不得照 D2 字面实现

票 04 落地后暴露:`type`/`tags` 在**任何读面都不渲染**,因此永远拿不到完整性记
录。而 D4 定了它们**只能 `write`**。两条一叠,本票建成后会是:

- 首次写 → 「从未被写过」放行 ✓
- 结算改过之后主 agent 再想改 → 有授权、但无完整性记录 → **永久拒绝**

拒绝方向是安全的,但它锁死的是一个正常操作。两条出路:让某个读面真的渲染
type/tags,或在 D2 里明确**集合字段豁免完整读要求**(理由:集合整体提交,不存
在「预算外看不见的行」,完整读要防的损失在集合上不成立)。

**未裁决之前不要动这一块。** 照 D2 字面实现会把这个陷阱铸进产品。

## Acceptance criteria

- [ ] 授权来自截断渲染 → `write` 覆盖已有内容被拒,报文指名该字段;来自完整渲
      染 → 放行。
- [ ] 同样那次截断授权下,`edit` 放行(读要求是两种模式的唯一差别)。
- [ ] 字段为空/从未被写过 → `write` 免除完整读要求。
- [ ] 他人写过该字段后,`write` 与 `edit` **都**被拒,且报文与「未授权」可区
      分。
- [ ] 上一笔是本写者自己 → 两种模式都放行(writing is reading 不变)。
- [ ] 同实体一长一短两个字段:长字段截断不阻塞短字段的 `write`。
- [ ] `edit` 成功后字段被盖章,下一个写者据此判失效。
- [ ] typecheck 干净;全套绿,只余既定的陈旧包守卫红。
