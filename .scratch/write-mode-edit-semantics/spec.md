# 写面 Edit 语义:一套 write/edit 词汇,两种读要求

**Status:** ready-for-agent
**Source:** S15069 T1049–T1058(事故诊断 → 五轮裁决 → peer 对抗审查 → 本 Rev 2)
**Rev 2 改动:** 否掉初稿的 D5(`edit` 免检读授权)与 D6(容忍无关并发变动),
两者皆为初稿自造而非 Edit 语义;补齐 peer 指出的两处未定义缺口。
**Supersedes(部分):** ADR-0001 的字段编辑动词 · ADR-0002 的 writer 表与节奏
条款 · ADR-0007 的结算独立 facade · ADR-0008 的授权准入基线

## Problem Statement

三件事压在同一条缝上。

**一、写模式有两套词汇。** turn/session 面(`note`)用逐字段 `mode:
overwrite | append`;段面(`remember`)用动词 `append` / `replace(old,new)`
——后者是 ADR-0001 为「字段即 markdown 行列表」专门定的,并明确让
overwrite/append 在段面退役。同一件事在两个面上叫两个名字,而 D5/D5a 当初写下
的「一套 mode 词汇,两个寻址面共用」从未达成。

**二、整字段覆盖在结构上不安全。** 所有字段都在 token 预算下渲染,超出即截
断。写者手里可能只有被截断的旧文,却被允许整份覆盖——门只查「看过没」「变过
没」,不查「看全了没」,于是覆盖会静默删掉看不见的行,连同别的写者落在不可见
区域的修改。

**三、有副作用的读已经炸了。** SessionStart 的段块槽各自是独立 hook 进程,按
设计开只读连接以避开并行进程抢写锁;ADR-0008 又要求注入记录读授权。两条各自成
立的决策对撞:授权 INSERT 在只读句柄上抛错。`milestones` 块被渲染器兜住,吐一
行 `timeline error: attempt to write a readonly database`;`fields` 块直接抛
穿,handler 的 catch 把整块吞掉——**无声消失**。每个 resume/compact 会话都在丢
两块注入,线上 0.12.1 即如此。

## Solution

**一套词汇:`write` 与 `edit`。**

- `write` — 整字段替换。文本字段替换全文,集合字段替换全集,可空字段配显式
  `null` 表示清空。
- `edit` — 在一个字段内把 `oldString` 精确换成 `newString`。找不到、命中多处
  都是响亮拒绝并指名是哪一种;`newString: ""` 即删除命中的那段。

`append` 退役,`replace` 作为独立动词退役(其行为即 `edit`)。

**两种模式的唯一差别是读要求。** 门对两者一视同仁——都要读授权,都受失效判
定。区别在于覆盖已有内容的 `write` 额外要求这次授权来自一次**未被截断的**该字
段渲染;`edit` 只需授权本身,截断的渲染也算数,因为它只承诺改动它精确匹配到的
那一段。

**读在 hook 路径上重新变回无副作用。** 段块槽不再记录读授权。授权基准回归「实
际渲染出内容」这一条,不做任何扩张。

## User Stories

1. 作为写者,我想只记一套模式词汇,这样在 turn 面和段面之间切换时不必重新学一遍。
2. 作为写者,我想用 `edit` 改一行而不必回传整个字段,这样长字段的小修改不再昂贵。
3. 作为写者,我想 `edit` 在截断的渲染上也能用,这样我不必为改一行先把整个字段读全。
4. 作为写者,我想 `oldString` 打不中时收到「没找到」而不是静默无操作,这样我知道我的假设错了。
5. 作为写者,我想 `oldString` 命中多处时收到「命中 N 处」而不是任选一处替换,这样我不会改错地方。
6. 作为写者,我想用 `newString: ""` 删掉一段,这样删除不需要第三个动词。
7. 作为写者,我想覆盖一个已有内容的字段前被要求先读全它,这样我不会静默删掉预算外的行。
8. 作为写者,我想在被拒时报文直接告诉我该怎么补读,这样我不必猜是哪个字段被截断了。
9. 作为写者,我想 `write` 一个从未有人写过的字段时直接放行,这样新建路径不必先读一个空东西。
10. 作为写者,我想上一笔是我自己写的字段直接放行,这样我不必为自己的连续修改反复重读。
11. 作为写者,我想别人在我读后动过这个字段时被拒,无论我用 `write` 还是 `edit`,这样我的修改不会落在我没见过的内容上。
12. 作为写者,我想被拒时能区分「没读过」与「读过但已失效」,这样我知道该读还是该重读。
13. 作为写者,我想给 `note` 的 `type`/`tags` 只能整集提交,这样集合语义不会被文本替换规则污染。
14. 作为写者,我想在段字段上第一次拥有整字段覆盖能力,这样重写一整块或清空一个字段不再是不可表达的操作。
15. 作为写者,我想继续用行列表组织段字段,这样 ADR-0001 的内容形态不因动词变化而变化。
16. 作为写者,我想往行列表加一行时有明确惯用法,这样 `append` 退役不留下操作空白。
17. 作为写者,我想在别人抢先加了一行时被拒而不是把我的行插到中间,这样按时间排的行列表不会乱序。
18. 作为写者,我想旧词汇被拒时报文直接给出新词,这样迁移不需要查文档。
19. 作为写者,我想 `edit` 之后字段仍被盖章,这样别的写者能察觉我动过它。
20. 作为结算子代理,我想用与主 agent **完全相同**的工具,只多一个 `commit`,这样我不需要第二套写规则。
21. 作为恢复会话的读者,我想 `[E<n>] · fields` 与 `[E<n>] · milestones` 两块重新出现在注入里,这样我不必手动 recall 才能看到当前任务状态。
22. 作为维护者,我想 hook 路径继续用只读连接,这样并行 SessionStart 进程不抢写锁。
23. 作为维护者,我想读授权表与 janitor 清扫保留,这样 `write` 的安全性不依赖调用方回传旧全文。
24. 作为写者,我想只在连续 20 个 turn 完全没维护过段字段时才被提醒,这样正常的密集维护不再被唠叨。
25. 作为维护者,我想 ADR-0001/0002/0007/0008 被显式修订而不是被悄悄绕过,这样后来者读到的决策史是连续的。
26. 作为维护者,我想签入的运行时 bundle 与工具描述同批更新,这样注入的教学与实际接口不脱节。

## Implementation Decisions

### D1 · 模式词汇统一为 `write` | `edit`

`note` 的逐字段 `mode` 映射与 `remember` 的动词枚举收敛到同一组词。`remember`
失去 `append` 与 `replace` 两个动词;字段写入统一表达为「哪个字段、什么模式」。
`create` / `attach` / `close` / `assign` 不受影响——它们是段的生命周期与归属操
作,不是字段写入。

### D2 · `write` 的语义与读要求

整字段替换。文本字段替换全文;集合字段替换全集;可空字段配显式 `null` 表示清
空(清空是一次写,不是「从未写过」,ADR-0008 原有语义不变)。

**覆盖已有内容时,本次授权必须来自一次未被截断的该字段渲染**([S15069/T1056]
裁决)。字段为空或从未被写过时不要求——那是新建路径,没有可丢的旧内容。

### D3 · `edit` 的语义与读要求

单字段内 `oldString` → `newString` 精确替换,沿用段面 `replace` 已有的实现与拒
绝形态:`oldString` 缺失或空 → 参数错误;字段内找不到 → 拒绝并回显
`oldString`;命中多于一处 → 拒绝并报出命中次数。`newString: ""` 删除命中段。

读要求只有读授权本身,截断的渲染也算数。理由:`edit` 只承诺改动它精确匹配到的
那一段,不触碰预算外的内容。

### D4 · 集合字段只接受 `write`

**范围限定在 `note` 面的 `type` / `tags`。** 段的 type/tags 由成员 turn 派
生、title 是 create-only,都不在 `SEGMENT_EDITABLE_FIELDS` 里,不受本条约束。

`note` 的 `type`/`tags` 拒绝 `edit`,报文说明理由(`oldString/newString` 对集
合无意义)。裁决理由:若为集合另定 `edit` 含义(增删元素),同一个词在文本字段
与集合字段上就是两件事。代价接受:加一个 tag 需重新提交全集,而这要求先读到它
——与 Edit 纪律一致。

### D5 · 门:两种模式同样受约束,差别只在读要求

**初稿的「`edit` 跳过读授权」作废。** [S15069/T1050] 的裁决是「看见」与「内容
一致」**两个前提并存**,不是前者可由后者蕴含;Edit 工具同样两者都要。写者可以
从过期的注入里猜出一个恰好唯一命中的 `oldString`,匹配因此不能替代授权。

两种模式一律走 ADR-0008 的三判次序(已授权且未失效 / 上一笔是自己 / 从未被写
过 / 否则拒),`write` 在此之上叠加 D2 的未截断要求。

被否决的替代:删掉授权表,令 `write` 也自证(调用同时交出旧全文与新全文)。契
约会更单一,但整字段覆盖本就是最贵的操作,再要求回传旧全文使其更贵
([S15069/T1052])。

### D6 · 失效判定对 `edit` 同样生效(初稿的松弛作废)

初稿写「别人改了同一字段的无关部分也放行」。核查后作废:Claude Code 的 Edit 工
具在文件自读后被外部修改时**会拒绝**并要求重读,初稿那条是自造的松弛,不是
Edit 语义;它还正是加行乱序的根源(见 D7)。

因此:字段在本写者读后被他人写过 → 两种模式一律拒,报「失效」并指名另一位写
者。

### D7 · 行列表的加行惯用法

ADR-0001 的「字段即 markdown 行列表」不变,但加行不再有专用动词。惯用法:锚定
末行做 `edit`(`oldString` 为末行,`newString` 为末行加新行);字段可整读且需
要重排时用 `write`。

**D6 恢复后并发乱序自动消失**:若他人抢先加了一行,本写者的字段已失效 → 被拒
→ 重读 → 看到新末行 → 锚定它加行。顺序由「失效即重读」保证,不需要末尾位置校
验这类专用机制。

工具描述须把这条惯用法写明——这是 `append` 退役后唯一的操作空白,不写明就会变
成写者反复试错的地方。

### D8 · 授权的完整性记录

`write` 要判「读全了没」,就需要知道上次渲染有没有截断这个字段。渲染器已经带着
逐字段的截断信号(`TruncationSignal`),把它接进授权记录即可:渲染记录授权时,
一并记下**本次完整交付了哪些字段**。

**这是本 spec 自己的设计决定,不在用户裁决内**,理由:它避免新增一条「全文读」
的读面参数,让完整性成为普通渲染的副产品——字段短到装得下预算时天然完整,长字
段则由写者提高预算重读来换取。拒绝报文必须指名是哪个字段被截断、补救动作是什
么,否则写者无从下手。

粒度是**逐字段**,而不是 ADR-0008 的实体级——`write` 是逐字段操作,实体级完整
性会让一个长字段的截断连坐同实体的短字段。

### D9 · hook 注入:段块槽不再记录读授权

段块槽在只读连接上运行,不传写者身份。**授权基准回归「实际渲染出内容」,不做扩
张**——初稿把它扩到「全体挂靠段」是过授权,花名册的溢出行明写
`(attached, not rendered here)`,没有渲染出内容就不该拿到授权。

三处已知缺口,记录在案而不在本 spec 修补:

- 掉出花名册当前页的挂靠段没有授权路径 → 显式 `recall(id="E<n>")` 补。
- closed 的挂靠段被段块选中却被花名册的 live 谓词排除,移除块授权后同样无授权
  路径 → 同上。
- 花名册候选取数上限 500,第 501 个活段永远不进页也不拿授权。

三者都以「显式 recall 一次」为出路,报文的 never-granted 分支本就指向它。

### D10 · `note` 的 `edit` 载荷形状

现行 `mode` 只是一个逐字段的 enum,`oldString`/`newString` 无处安放;而
`note.ts` 的解析器把**任何非 append 的 mode 当整字段覆盖**——只改 enum 会让
`edit` 静默变成整写。

因此 `mode.<field>` 从字符串扩为可辨识联合:`"write"`,或
`{ mode: "edit", oldString, newString }`。一次调用可对不同字段各取其一。
`type`/`tags` 上出现 edit 形态 → 按 D4 拒绝。字段值与 edit 形态同时出现 → 参
数错误(edit 的新内容在 `newString` 里,不在字段值里)。

### D11 · 段字段的整字段写实现

段面此前只有 append 与字面替换,**没有整字段写**;`applySegmentWrites` 是结算
的 CAS 路径且明确排除 Working State。`write` 因此是新增能力,实现须覆盖
`SEGMENT_EDITABLE_FIELDS` 全部八个字段,并明确:空串与 `null` 的语义、写后引用
关系(citations)重建、FTS 重索引。这些是既有 append/replace 路径已经承担的职
责,新路径不得漏掉。

### D12 · 结算面与主 agent 完全一致

[S15069/T1056] 裁决:结算子代理的工具与主 agent **相同**,只多一个 `commit`。
结算的输入形状补上同一套 `mode`,SDK 与提示词里「no append」一类的差异化措辞删
除。ADR-0007「结算是不同 facade」加补注说明这条收敛。

### D13 · 维护节奏化简

[S15069/T1057] 裁决:「不足 10 turn 又写 → 太频繁」整条退役,只保留**连续 20
个 turn 没更新过段的任何字段才提醒**。

连带:`decisions` 的豁免**自动消失**——它原本只豁免「太频繁」那一句,该句退役
后无处可豁免,ADR-0002 那条「a lost ruling is the costliest loss」的理由也随之
作废。这不是裁掉一个例外,是例外失去了存在的前提。

### D14 · 旧词汇的拒绝形态

`overwrite` / `append` / `replace` 被送来时,拒绝并在报文里指名替代词。仅靠
zod 的 enum 会得到无信息的通用报错,因此退役字面量需保留在 schema 里并挂自定义
报文,沿用已有先例(退役的 `topic`、退役的 `truncate`/`view`)。两个入口
(`note`、`remember`)都要测。

### D15 · 决策记录与消费者同步

修订(非补注)ADR-0008 的授权准入基线——它现行文字是全量 grant 语义,不涵盖
D2 的未截断要求与 D8 的逐字段完整性。补注 ADR-0001(字段编辑动词)、ADR-0002
(writer 表的动词列、节奏条款)、ADR-0007(结算 facade 收敛)。

同批更新的消费者清单以**实际教学源**为准:`definitions.ts` 的工具描述、结算的
提示词与 SDK 工具描述、以及签入的 `plugin/scripts/*.cjs`——那是 `plugin/.mcp.json`
指向的运行时入口,不重建就等于没上线。Memory Rubric 与 mnemo-recall skill 当前
**没有**写模式教学,不在清单内。

## Testing Decisions

好测试只断言外部行为:一次工具调用进去,存储状态与回执出来。不断言私有函数被
调用过、不断言中间数据结构形状。

三条缝都是既有的,本 spec 不新增缝;但「已有缝足够」只在补齐下列行为矩阵后成
立——现有测试**不会**捕获本批要修的任何一个问题。

**主缝:两个工具入口**(`tests/mcp/note*.test.ts`、`tests/mcp/remember*.test.ts`)

- `edit` 的三态:唯一命中成功、找不到拒绝、多处命中拒绝并报次数。
- `edit` 的载荷形状:辨识联合解析、字段值与 edit 并存拒绝、`type`/`tags` 上的
  edit 拒绝。
- `write` 覆盖已有内容:授权来自截断渲染 → 拒绝且报文指名字段;来自完整渲染 →
  放行。字段为空/从未被写过 → 免除该要求。
- 失效:他人写过该字段后,`write` 与 `edit` **都**被拒,报文区分失效与未授权。
- `edit` 成功后字段被盖章(下一个写者据此判失效)。
- 段的八个可编辑字段各自的 `write`:空串、`null`、引用重建、FTS 可检索。
- 旧词汇 `overwrite`/`append`/`replace` 在两个入口都得到指名替代词的报文。
- 节奏回执:连续 20 turn 无段字段更新才出提醒;密集写入不再出「太频繁」;
  `decisions` 与其他字段回执一致。

**已有缝二:门的单元测试**(`tests/db/write-gate.test.ts`)

逐字段完整性记录的判定表:同实体一长一短两个字段,长字段截断不得连坐短字段的
`write`。

**已有缝三:hook 处理器**(`tests/hooks/session-composition.test.ts` 及处理器测试)

- **必须用只读的、文件落盘的数据库句柄**渲染段块,断言块头出现、内容非错误
  行、且 `write_gate_reads` 无新增。现有 hook 测试用可写的内存库且多数不传
  readerId,这正是事故未被拦下的原因。
- 花名册的授权仍以实际渲染出的页项为准:溢出行(仅指路、无内容)不得拿到授权。

**结算面**:其工具注册与主 agent 一致(D12)须在结算的 SDK 注册边界上断言,而
非仅靠提示词文本。

## Out of Scope

- 视图与渲染器(金样例、pageBudget、搜索形态)——已在读写契约批次内闭合。
- 段块 handler 的宽 catch 把渲染异常吞成「没有这一块」这一行为本身。D9 修的是
  对撞的成因;吞异常值得单独审视,但本批不动它,因此本 spec 不承诺「失败一定
  可见」。
- 旧纪元评分残体(`selectMilestoneTurns`)——已单独冻结。
- 纪元切点不移动。
- `create` / `attach` / `close` / `assign` 四个段生命周期动词的语义。
- D9 记录的三处授权缺口(溢出、closed 挂靠、候选上限 500)——出路是显式
  recall,不在本批修补。

## Further Notes

**事故可以先行止血。** D9 与 D1–D14 的词汇工程无依赖。线上每个 resume/compact
会话都在丢两块注入,它作为第一张票单独落地、单独发版,不等整批。

**已知代价,记录在案。** 段字段的行列表加行是最常见的写操作,`append` 退役后它
从一个专用动词变成 D7 的锚定惯用法,并且在并发下会以「失效重读」的形式付出一次
往返。这是词汇统一换来的直接成本,不是疏漏;若实际使用中证明它足够刺痛,回头的
选项是给 `edit` 定义一个末尾锚定的简写,而不是把 `append` 请回来。

**批次外顺出的一笔旧账,记下免得丢。** timeline 的两个 turn 渲染器字段标签不一
致:统一 turn 视图输出 `- prompt:`,而它自己的文档注释写的是「then
`- content:`」(代码与注释互相矛盾);段视图的兄弟渲染器输出 `- content:`,喂进
去的却是 prompt 文本(标签与值不符)。两者都是上一批视图修复的落地残留,不在本
spec 范围内,未开票。

**本 Rev 的两条作废来自同一个错误。** 初稿的 D5 与 D6 都是把「Edit 语义」当成
了「匹配即足够」,而 Edit 工具实际要求读过、自读后未变、精确匹配三者俱全。peer
的对抗审查与对 Edit 工具行为的复核各自独立地指向同一处。
