# Recall V2：统一记忆检索接口

## 动机

当前 recall 有 13 个参数，职责混杂：选择靠参数组合隐式推断层级，`expand_turns` 混合了选择和渲染，搜索和浏览是互斥的两条代码路径。此外，`buildExtractionContext`（Mnemosyne 提取上下文）和 `formatPrimarySession`（SessionStart 注入上下文）各自实现了独立的渲染逻辑，与 recall 大量重复。

V2 将 recall 重构为统一接口：选择与渲染正交，覆盖浏览、搜索、提取上下文三个场景。数据检索层同时为 SessionStart context hook 提供底层支持。

## 参数

```typescript
interface RecallInput {
  scope: "sessions" | "turns" | "observations";  // 必填，展示层级
  session?: number | number[] | string;   // session 选择器
  turn?: number | number[] | string;      // turn 选择器（prompt_number）
  obs?: number | number[] | string;       // observation 选择器（全局 DB id）
  query?: string;         // 全文搜索
  type?: string;          // observation 类型过滤
  file?: string;          // 文件过滤
  after?: number;         // epoch 下限
  before?: number;        // epoch 上限
  time?: string;          // 日期语法糖
  depth?: "collapsed" | "expanded" | "full";  // 子级渲染深度
}
```

### `scope`（必填）

决定返回结果的展示粒度——每条结果是一个 session、一个 turn 还是一个 observation。

选中的实体本身始终展开，`depth` 控制的是其**子级**的渲染深度。

**父级 header**：当 `scope` 低于选择器的层级时，输出自动带父级 header。例如 `recall(scope="turns", session=42)` 会在 turn 列表前输出 session 42 的 header（Session ID、Project、Title、Description），确保消费者能获取上下文元信息。

### `session`、`turn`、`obs`

三个独立选择器，各自支持三种输入格式：

| 格式 | 类型 | 示例 | 含义 |
|------|------|------|------|
| 单值 | `number` | `session=42` | 单个 |
| 数组 | `number[]` | `turn=[3,5,7]` | 列表 |
| 范围 | `string` | `turn="3..7"` | 范围 → [3,4,5,6,7] |

选择器缩小搜索空间，`scope` 决定在该空间内以什么粒度展示：

```python
recall(scope="turns", session=42)              # session 42 → 列出 turns
recall(scope="observations", session=42)       # session 42 → 列出所有 observations
recall(scope="turns", session=42, turn=[3,5])  # session 42 的 T3、T5
recall(scope="observations", session=42, turn=5, obs=7)  # 具体 observation
```

**层级校验**：每个选择器必须属于其父级。`obs=7` 指定时，该 observation 必须属于指定的 `session`/`turn`。不匹配时返回 parameter error，不静默忽略父级约束。

### `query`

FTS5 全文搜索，在选择器和时间限定的范围内搜索。可与 `type`/`file` 叠加。

### `type`

按 observation 类型过滤：`bugfix`、`feature`、`refactor`、`change`、`discovery`、`decision`。

当 `scope="sessions"` 或 `scope="turns"` 时，返回包含匹配 observation 的 session/turn。

### `file`

按文件路径过滤，匹配 `files_read` 或 `files_modified` 字段。

### `after`、`before`、`time`

时间过滤拆为精确控制和语法糖：

| 参数 | 类型 | 用途 | 示例 |
|------|------|------|------|
| `after` | `number` | epoch 下限（>=） | `1712448000` |
| `before` | `number` | epoch 上限（<=） | `1712534400` |
| `time` | `string` | 日期语法糖，解析为 after/before | `"-7d"`、`"2026-04-07"` |

`time` 的解析规则：

| 格式 | 含义 | 等价 |
|------|------|------|
| `"-7d"` | 最近 7 天 | `after = now - 7d` |
| `"-2w"` | 最近 2 周 | `after = now - 14d` |
| `"2026-04-07"` | 某一天 | `after = 当天 00:00, before = 当天 23:59` |
| `"2026-04-01..2026-04-07"` | 日期区间 | `after = 04-01 00:00, before = 04-07 23:59` |

`after`/`before` 与 `time` 同时指定时取交集。

### `depth`

子级渲染深度，默认 `"collapsed"`：

| depth | 子级行为 | 递归 | 自动省略 |
|-------|---------|------|---------|
| `collapsed` | 标题 + 统计（`[T1] Fix auth \| 💡2 🔧5 [extracted]`） | 否 | 是 |
| `expanded` | 直接子级展开，孙级 collapsed | 否 | 是 |
| `full` | 所有后代递归展开 | 是 | 是 |

## 内建自动行为

| 规则 | 条件 | 行为 |
|------|------|------|
| 自动省略 | 单层级 > 50 项 | head 5 + 中间均匀采样 5 + tail 10，间隔处显示 `... N omitted ...`。**pending/stale 状态的 turn 始终保留，不参与省略** |
| 字段截断 | 所有模式，200 字符 | 超出截断 + `[use replay(session=S, turn=T) for full content]` |
| 状态标签 | 始终 | 每个 turn 显示 `[pending]`/`[stale]`/`[extracted]`/`[skipped]`/`[undone]` |

## 用法示例

### 浏览

```python
recall(scope="sessions")                                    # 最近 sessions
recall(scope="sessions", time="-7d")                        # 最近 7 天
recall(scope="turns", session=42)                           # S42 的 turns
recall(scope="turns", session=42, depth="expanded")         # S42 的 turns 展开
recall(scope="turns", session=42, turn="3..7")              # S42 的 T3-T7
recall(scope="turns", session=[40,42])                      # 两个 session 的 turns
recall(scope="observations", session=42, turn=5)            # S42/T5 的 observations
recall(scope="observations", session=42, turn=5, obs=7)     # 具体 observation
recall(scope="observations", obs=7, depth="expanded")       # observation 完整详情
```

### 搜索

```python
recall(scope="sessions", query="auth")                      # 搜索 sessions
recall(scope="turns", query="auth", session=42)             # 在 S42 内搜索 turns
recall(scope="observations", type="bugfix")                 # 全局 bugfix observations
recall(scope="observations", type="bugfix", time="-30d")    # 近 30 天 bugfix
recall(scope="observations", file="src/auth.ts")            # 涉及该文件的 observations
recall(scope="turns", query="race condition", type="bugfix", time="2026-04-01..2026-04-07")
```

### Mnemosyne 提取上下文

```python
recall(scope="turns", session=42, depth="expanded")
```

直接调用 `recallMemory()`，输出包在 `buildMnemosynePrompt()` 里，不再维护独立的 `buildExtractionContext`。

与现有实现的差异（deliberate behavior change，不是等价重构）：

| | 现有实现 | V2 |
|---|---------|-----|
| 分档渲染 | head 3 collapsed + 中间 omitted + tail 3 expanded | 统一自动省略（>50 项：head 5 + 采样 5 + tail 10） |
| 字段截断 | 1500 字符 | **200 字符**（刻意收紧） |
| pending/stale bypass | 自有实现 | 内建于自动省略规则（pending/stale 始终保留，不参与省略） |
| 状态标签 | 有 | 有（无变化） |

**截断收紧理由**：1500 字符的长 prompt/response 对提取 Agent 判断"这个 turn 做了什么"价值有限，200 字符足够提供上下文。需要原文时提取 Agent 可调用 `replay()`。

### SessionStart 注入上下文

**不等价于简单的 `recall()` 调用组合。** 当前 context hook 有独立的渲染契约：

| 层级 | 范围 | 渲染规则 |
|------|------|---------|
| Primary（当前 session） | 1 个 | 展开，最后 3 turns 展开含 observations，其余 collapsed |
| Next 2 | 2 个 | Session collapsed + 最近 5 turns collapsed |
| Last 2 | 2 个 | Session header only，无 turns |

此外 context hook 有独立的截断预算（description 60 字符、prompt 120、response 200、insight 80、每 turn 最多 3 obs），以及 session 锚定逻辑（以 `content_session_id` 而非 `started_at_epoch` 确定 primary）。

**Phase 2 策略：** SessionStart 保持现有代码不动。其 3 档深度、紧截断预算和 `content_session_id` 锚定逻辑与 recall 的通用渲染差异过大，强行统一收益不大。

## 消费者模型

不抽共享数据层。三个消费者各自调用所需的函数：

| 消费者 | 调用方式 | 渲染 |
|--------|---------|------|
| recall MCP tool | `recallMemory(db, input)` | 通用渲染（scope/depth/省略/截断） |
| Mnemosyne | `recallMemory(db, { scope: "turns", session: id, depth: "expanded" })` | 直接使用 recall 输出，包在 `buildMnemosynePrompt()` 里 |
| SessionStart | 保持现有代码（`getRecentSessions` + `getTurnsForSession` + 自有渲染） | 3 档深度 + 紧截断 + header |

## 迁移策略

旧参数在 `recallMemory` 入口做一次性映射。大部分直接对应，两个 breaking change 明确标注：

### 兼容映射

| 旧参数 | 映射 |
|--------|------|
| `session=42` | `session=42`（无变化） |
| `session=42, turn=3` | `session=42, turn=3`（无变化） |
| `observation=7` | `obs=7`（重命名） |
| `expand_turns=[1,3]` | 见下方 breaking changes |
| `from_epoch=X, to_epoch=Y` | `after=X, before=Y`（重命名） |

### Breaking changes

| 旧功能 | 状态 | 替代方案 |
|--------|------|---------|
| `around="S12", before=2, after=2`（按条目数滑窗） | **移除** | Agent 先 `recall(scope="sessions")` 找到 S12 的时间，再用 `after`/`before` epoch 查范围 |
| `expand_turns=[1,3]`（全部列出 + 部分展开） | **移除** | V1 语义是"列出所有 turns，但只展开 T1 和 T3"。V2 的 `turn=[1,3], depth="expanded"` 会只返回 T1/T3，丢失其余 turns。V2 无法在列表视图中混合展开级别——要看全部 turns 用 `recall(scope="turns", session=42)`，要看具体 turn 详情用 `recall(scope="observations", session=42, turn=3)` 钻入 |

### Observation ID 保留全局 DB id

V2 保留 `[O7]` 全局 DB id 语义。

- `obs=7` 使用全局 DB id，与 `[O7]` 渲染标签一致
- Agent 从标签直接提取数字用于后续查询

**为什么不用 per-turn 序号：** 当前 `save_turn` 重提取时先 `DELETE FROM observations WHERE turn_id = ?` 再重插（`turns.ts:152-157`），observation 数量和顺序可能变化。Per-turn 序号会静默指向不同 observation；全局 DB id 至少 loud fail（not found）。稳定性优先于语义一致性。

## 设计决策记录

1. **`scope` 必填**：消除隐式层级推断，每次调用都明确说明返回什么粒度的数据。
2. **独立选择器取代 `id` 路径**：`session`/`turn`/`obs` 各自独立，支持单值、数组和范围语法糖（`"3..7"`）。比 `id="42-5-7"` 路径语法更灵活（支持非连续选择、跨 session 查询），不需要 `parseIdPath`，层级校验各参数独立验证。
3. **`after`/`before` + `time` 分层**：`after`/`before` 是 epoch 数字，精确控制；`time` 是日期语法糖（`"-7d"`、`"2026-04-07"`），解析为 after/before。同时指定取交集。对应 claude-mem 的 `dateStart`/`dateEnd` 模式。
4. **状态标签默认显示**：`[pending]`/`[stale]` 等对浏览和提取都有价值，不需要开关。
5. **自动省略（50 项）**：head 5 + 中间均匀采样 5 + tail 10。中间采样保留时间线轮廓，不是完全黑箱。pending/stale 状态的 turn 始终保留，不参与省略——Mnemosyne 依赖此行为确保不遗漏需要处理的 turn。
6. **统一字段截断（200 字符）**：所有模式、所有字段一视同仁，不再按 description/prompt/response 分别设预算。
7. **`depth` 三档**：`collapsed`（标题+统计）、`expanded`（直接子级展开、孙级 collapsed）、`full`（递归展开所有后代）。三档均有自动省略和 200 字符截断。
8. **Observation ID 保留全局 DB id**：per-turn 序号在重提取（delete + re-insert）后会静默漂移，全局 DB id 至少 loud fail。`[O7]` 标签直接对应 `obs=7`，Agent 可从标签构造查询。
9. **SessionStart 不动**：context hook 有特定的截断预算、3 档深度和 `content_session_id` 锚定逻辑，与 recall 通用渲染差异过大。保持现有代码，不强行统一。
12. **Mnemosyne 直接调 `recallMemory()`**：不抽共享数据层，不维护独立的 `buildExtractionContext`。pending/stale bypass 内建于自动省略规则，Mnemosyne 不需要特殊路径。
10. **`around` 滑窗是 breaking removal**：`around` 是基于条目数（前后 N 个 session）的滑窗，不是时间范围。V2 `after`/`before` 只支持时间维度，语义不可替代。
11. **`expand_turns` 是 breaking removal**：V1 的 `expand_turns=[1,3]` 语义是"列出全部 turns，但只展开指定的"——混合了选择和渲染。V2 的 `turn` 是纯选择器（过滤结果集），`depth` 是纯渲染（全局生效），两者正交，无法复现"全部列出 + 部分展开"。Agent 通过两步操作替代：先 `scope="turns"` 浏览全部，再 `scope="observations"` 钻入感兴趣的 turn。
